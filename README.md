# Система «Радар» v5.6.2

[English version](README.en.md)

Telegram-бот, который следит за городскими угрозами и авариями ЖКХ по вашим адресам.
Сообщения публичных каналов служб ЖКХ, МЧС, администраций города, района и области,
а также RSS-ленты СМИ разбирает ИИ Google Gemini, после чего события сопоставляются
с сохранёнными локациями.

## Установка

Одной командой на чистой Debian или Ubuntu:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh)
```

Установщик на английском:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh) --lang=en
```

Надёжнее — скачать скрипт заранее и запустить файлом. При обрыве связи
подстановка `<(curl ...)` отдаёт скрипт не целиком, и хотя установщик это
переживёт (тело обёрнуто в функцию, неполный файл просто не выполнится),
скачанный файл можно перезапустить, не выкачивая заново:

```bash
curl -fsSLo radar-install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
bash radar-install.sh
```

Скрипт сам создаст `~/radar_bot`, развернёт исходники, спросит токены, соберёт Docker-образ
и запустит контейнер. Повторный запуск той же команды обновляет бота: база `data/db.json`
и `.env` сохраняются.

Установщик проверяет компоненты системы, при необходимости обновляет пакеты
и образы Docker, диагностирует предыдущую установку и **спрашивает, как
поступить**: обновить поверх, переустановить, начать с чистого листа или
только снять копию. Если бот падал, установщик разбирает лог, называет
вероятную причину и подсказывает подходящий вариант — но выбор остаётся
за вами. Перед запуском бота выполняется диагностика внутри контейнера;
при ошибке бот не стартует, а вы получаете отчёт. Весь ход работы пишется
в `~/radar_bot/installer_log.txt`.

Флаги: `--backup` (снять копию и выйти), `--reset` (полный сброс: копия,
удаление базы, установка с нуля), `--recreate-env` (перезаписать настройки),
`--reinstall` (принудительная полная переустановка), `--skip-updates`
(не обновлять пакеты системы),
`--no-cache` (пересборка без кэша), `--logs` (показать логи),
`--rollback` (вернуть предыдущую версию из снимка),
`--uninstall` (снести контейнеры и образ, данные остаются), `--version`, `--help`.

Перед каждым обновлением установщик сохраняет снимок текущей установки.
Если новая версия не запускается, он предлагает откатиться на предыдущую
или поставить проверенную 3.3.5.

Установка из клона репозитория:

```bash
git clone https://github.com/Chistovik92/radar.git && cd radar
cp .env.example .env && nano .env      # задайте DB_PASSWORD (без символа $)
docker compose up -d --build
```

Поднимается один контейнер — `radar_container`. База по умолчанию SQLite:
файл `data/radar.db` рядом с ботом, отдельный сервер не нужен. Схема создаётся
при первом старте, данные версии 3.x из `data/db.json` переносятся автоматически.

Установщик спрашивает про базу при **любом** способе установки — в том числе
при обновлении поверх. Переключение между базами предупреждает, что данные
сами не переезжают, и просит подтверждения.

Для машины помощнее доступен PostgreSQL:

```bash
# в .env: DB_BACKEND=postgres, DB_PASSWORD=... (без символа $)
docker compose --profile postgres up -d --build
```

С 4.9.9.3 установщик подбирает настройки PostgreSQL под память машины
(`PG_SHARED_BUFFERS` и соседние в `.env`): `shared_buffers` — восьмая часть
памяти, но не выше 128 МБ, чтобы база не упёрлась в лимит своего
контейнера. Заданное руками он не трогает; без этих строк база стартует
с прежними значениями.

## Логика оповещений

| Тип события | Область | Формат сообщения |
|---|---|---|
| 🛸 БПЛА, ракетная опасность, воздушная тревога, работа ПВО | весь город | одно сообщение на город со списком всех совпавших локаций в нём |
| 🆘 МЧС: ЧС, штормовое предупреждение, эвакуация, пожары | город, либо адресно, если названы улицы | вместе с городскими или адресными |
| 🛠 ЖКХ: вода, свет, газ, отопление, порывы, ремонты | адресно — улица и дом | отдельное сообщение на группу локаций |
| 📵 «Белые списки» связи | весь город | автоматически добавляются к оповещению о БПЛА |
| ✅ Отбой опасности | весь город | отдельное сообщение с другим сигналом |
| 🌤 Погода | точка локации | отдельное сообщение, блок на каждую группу |

Дополнительные правила:

- Локаций у пользователя может быть **сколько угодно**.
- Локации ближе **1 км** друг к другу (связность транзитивная) объединяются в одну группу,
  и вся информация по ним выводится вместе. Радиус меняется через `CLUSTER_RADIUS_M`.
- В начале каждого сообщения перечислены **совпавшие локации**.
- О «белых списках» в пабликах почти не пишут — операторы вводят их молча.
  Поэтому предупреждение не ищется в новостях, а выдаётся автоматически вместе
  с оповещением о БПЛА или ракетной опасности: что перестанет работать,
  что продолжит и как связаться.
- Отбой опасности («опасность снята», «режим отменён») распознаётся отдельно
  и приходит спокойным сообщением с зелёным маркером, а не как новая тревога.
  К нему добавляется примечание, что «белые списки» могут отключить в ближайшее
  время — связь обычно восстанавливают не сразу.
- Новости из RSS-лент и посты из Telegram-каналов снабжаются ссылкой
  на оригинал (у постов — с 4.9.9.2).
- Дом сопоставляется точно, поддерживаются диапазоны вида `12-20`. Если дома не названы —
  срабатывает вся улица; если не названа улица, но назван район — сработает район;
  общегородская авария ЖКХ приходит на все локации этого города.
- **Пересказ прошедшей опасности — сводка, а не тревога** (с 4.9.9.2). Новость
  «вечером была объявлена ракетная опасность, она действовала с 21:10 до 22:40»
  уходит в утреннюю или вечернюю сводку как случившееся. Решает время самого
  события по смыслу текста, а не слова «ракетная опасность» в заголовке.
  Если рядом есть призыв укрыться или «до отбоя» — это по-прежнему тревога:
  промолчать о живой опасности хуже, чем прислать лишнее.
- **Памятка — не авария** (с 4.9.9.2). Инструкция о действиях при прорыве
  трубы или запахе газа, номера аварийных служб приходят целиком, со ссылкой
  на оригинал и спокойным заголовком «ℹ️ Памятка» — без «ЖКХ и аварии на
  сетях» и без опасности. Переслать пост средствами Telegram бот не может:
  каналы он читает через веб-превью, а не как участник.
- **Реклама VPN вырезается** (с 4.9.9.3, возможность «Скрывать рекламу VPN»).
  Каналы и СМИ вставляют в посты рекламу VPN-сервисов; бот её не
  пересылает. В оповещениях, памятках и сводках рекламный абзац
  заменяется пометкой «[реклама VPN-сервиса скрыта]» — без партнёра:
  реклама внутри тревог недопустима, в том числе своя. В новостных
  подборках вместо рекламных постов — одна строка партнёрского проекта.
  Новость про VPN (например, о блокировках) рекламой не считается:
  нужны и упоминание VPN, и признак рекламы — промокод, цена,
  маркировка «Реклама», erid.

### Что происходит, когда что-то ломается (с 4.9.8.14)

Оповещения важнее всего остального в системе, поэтому их путь защищён отдельно.

- **Фоновый цикл под надзором.** Если задача мониторинга умрёт, бот не станет
  дальше отвечать на команды как ни в чём не бывало: сторож поднимет цикл
  заново и напишет администраторам. Не поднявшись с трёх попыток, бот
  останавливает сам себя — контейнер с `restart: unless-stopped` запустится
  заново. Молча работать без тревог он не будет.
- **Видно снаружи.** Цикл отмечается в `data/heartbeat` на каждом витке.
  Эту отметку читает `HEALTHCHECK` контейнера (`docker ps` покажет
  `unhealthy`), а в `/stats` есть строка «Последний проход».
- **Повтор при сбое сети.** Обрыв связи с Telegram и ответ «подождите»
  не означают потерянную тревогу: отправка повторяется, а отметка
  «доставлено» ставится только после успеха — иначе оповещение уйдёт
  следующим циклом.
- **Придержанное не теряется.** Отложенное тихими часами хранится в базе
  и переживает перезапуск; предел очереди свой у каждого получателя.
- **Сбой раздела объясняется.** Упавший обработчик отвечает человеку, что
  не получилось, вместо мёртвой кнопки.
- **Метрики и здоровье — одним экраном** (с 4.9.9.3). `/metrics`
  или «Управление → 🩺 Метрики и здоровье»: доставленные оповещения
  и задержка от поста в источнике до сообщения (медиана и 90%),
  расход квоты ИИ, доля недоступных источников, память, диски,
  размер базы и состояние контейнеров.

## Источники

Наборы по городам лежат в `radar/presets.py`: Саратов, Москва, Санкт-Петербург,
Казань, Самара плюс федеральные каналы, которые подключаются всегда. Какие
наборы включить при первом запуске — переменная `SOURCE_CITIES`.

Источники опрашиваются **параллельно**, но не более `SOURCE_CONCURRENCY`
одновременно (по умолчанию 6). До 4.7.7 обход был последовательным:
замер на боевом сервере показал 51 секунду на цикл при интервале 180 —
бот больше четверти времени ждал сеть, загрузив процессор на два процента.
Предел нужен, а не «все разом»: десятки одновременных запросов к `t.me`
с одного адреса выглядят как выкачивание, а расплачивается за это система
оповещения.

Списки устаревают молча: канал переименовали, ведомство ушло в другой мессенджер,
лента отдаёт 404. Проверка:

```bash
python3 tools/check_sources.py --all-presets
python3 tools/check_sources.py --file data/db.json --json report.json
```

Инструмент показывает дату последней публикации, помечает давно не обновлявшиеся
источники и отдельно — те, что упоминают переход в MAX.

То же самое доступно прямо в боте: кнопка «🔍 Проверить доступность» в панели
модератора или команда `/checksources`. По итогам можно одной кнопкой убрать
все недоступные источники.

Проверка не ограничивается кодом ответа: `t.me/s/<канал>` отдаёт 200 и для
закрытых, и для несуществующих каналов, поэтому проверяется наличие блоков
сообщений и дата последнего поста.

## Выгрузка и загрузка источников

В панели модератора есть кнопки «⬇️ Скачать список» и «⬆️ Загрузить список».
Выгрузка — версионированный JSON, который прочитают будущие версии бота:
формат помечен номером схемы, неизвестные поля игнорируются, отсутствующие
берутся по умолчанию. Загрузка принимает также простой список каналов текстом
и `db.json` от версии 3.x — так переносятся настройки со старой установки.

Выгрузка доступна модераторам, загрузка — администраторам.

## Погода

Сводка построена как в погодных приложениях: крупное текущее значение
с описанием, строка деталей (ощущается, ветер с порывами, влажность, давление),
почасовая таблица на 8 часов со столбиком температуры и вероятностью осадков,
прогноз на три дня, время восхода и заката. Почасовая часть выводится
моноширинным блоком, иначе колонки разъезжаются.

Для каждой группы локаций — отдельное сообщение.

## Часовой пояс

Города пользователей лежат в разных поясах, поэтому время у каждого своё.
Пояс выбирается в настройках оповещений и задаёт смысл трём вещам сразу:
тихим часам, времени погоды и доставке новостных подборок. Пока пояс
не выбран, берётся пояс сервера — как было до 4.8.4.4.

Подписи зависят от языка. По-русски отсчёт идёт от Москвы (`МСК+2`):
на русскоязычном пространстве о времени говорят именно так, и `UTC+5`
человеку из Саратова ничего не сообщает. По-английски — от Гринвича
(`UTC+5`).

Хранится смещение, а не название зоны. Плата за простоту — переход
на летнее время: смещение его не отслеживает. Для России это безразлично,
перевода стрелок нет с 2014 года; пользователю из Европы или США раз
в полгода придётся поправить выбор.

## ИИ и расход квоты

Используется Google Gemini (`google-genai`). Бесплатный тариф жёстко ограничен по числу
запросов (порядка 10 в минуту и несколько сотен в сутки), поэтому расход снижается
четырьмя способами:

1. **Предфильтр** — сообщения без ключевых слов ЖКХ/ЧС/БПЛА/связи вообще не уходят в модель;
   на городских каналах это отсекает большую часть ленты.
2. **Пакетный разбор** — до `AI_BATCH_SIZE` новостей в одном запросе.
3. **Кэш по хэшу текста** — одна новость анализируется один раз для всех пользователей,
   расход не зависит от числа подписчиков.
4. **Учёт RPM/RPD с резервом** — `AI_RESERVE` суточных запросов доступны только
   ИИ-ассистенту, фоновый анализ до них не дотягивается. После ответа 429 фон встаёт
   на паузу `AI_COOLDOWN`, а диалог продолжает работать.

Для разбора используется более дешёвая модель (`GEMINI_MODEL_ANALYSIS`,
по умолчанию `gemini-3.5-flash-lite`), для диалога — `GEMINI_MODEL`
(`gemini-3.6-flash`) с включённым поиском в интернете. Расход — `/quota`.

### Устойчивость к отключению моделей

Google выводит модели из обращения быстрее объявленных дат: `gemini-2.5-flash`
был закрыт для новых ключей задолго до официальной даты отключения, и запросы
стали возвращать 404. Поэтому имя модели не зашито намертво:

* при старте бот запрашивает `models.list` и выбирает первую доступную ключу
  модель из списка кандидатов;
* при ответе 404 модель понижается на лету, и запрос повторяется на следующей;
* `GEMINI_MODEL` в `.env` — приоритетный кандидат, а не жёсткое требование;
* команда `/models` (администратор) показывает выбранные и доступные модели.

Учтены и различия поколений: для 3.x не отправляются устаревшие `temperature`,
`top_p`, `top_k`, вместо `thinking_budget` используется `thinking_level`,
а история диалога не заканчивается ходом роли `model` — иначе API вернёт 400.

Модель возвращает строгий JSON: категории, уровень важности, масштаб, город, район,
улицы с домами и краткую суть.

Если `GEMINI_API_KEY` не задан или Gemini недоступен, включается **эвристический разбор**
по ключевым словам с извлечением улиц и домов — бот продолжает оповещать, помечая такие
сообщения как «без ИИ».

ИИ-ассистент в чате доступен с роли «Модератор»: обычное сообщение или `/ai вопрос`,
`/aireset` очищает контекст.

## Команды

`/start`, `/menu` — меню - `/id` — ваш ID и роль - `/cancel` — сбросить ввод -
`/help` — справка - `/vpn` — о проекте HydraSite - `/ai`, `/aireset` — ассистент (модератор+) - `/quota` — расход квоты (модератор+) -
`/stats`, `/models` — статистика и модели (админ+) - `/features` — возможности - `/logs`, `/logtail`, `/logclear` — журналы (суперадмин) -
`/check <ссылка>` — проверка ссылки на признаки мошенничества (флаг «Проверка ссылок»)

## Музыка и внешнее хранилище

Треки лежат в `data/music` рядом с ботом. На одноплатнике место
кончается быстро — каталог можно вынести на внешний носитель:

```bash
# на сервере, один раз: флешка/диск монтируется в ~/radar_bot/data/music
sudo mount /dev/sdX1 /root/radar_bot/data/music

# навсегда — строка в /etc/fstab (подставьте свою файловую систему)
echo '/dev/sdX1 /root/radar_bot/data/music ext4 defaults,nofail 0 2' | sudo tee -a /etc/fstab
```

Никаких настроек в боте не нужно: каталог тот же. Альтернативно
можно указать путь переменной `MUSIC_DIR` в `.env` (контейеру нужен
доступ к этому пути — добавьте его в `volumes` в `docker-compose.yml`).

Два предостережения:

- **`nofail` обязателен**: без него сервер не загрузится, если носитель
  отошёл. Бот без музыки живёт, сервер без диска — нет.
- носитель должен переживать частую запись: дешёвая флешка умрёт
  за месяцы; SSD или HDD — норм.

Заполненность всех дисков (включая внешний) видна в ночном отчёте —
тумблер «Наблюдение за дисками» в `/features`; письмо приходит, когда
место подходит к концу. Кнопка «🗜 Сжать» в карточке трека пережимает
его в opus при битрейте исходника — вес падает в разы, на слух
разницы нет.

### Подборки и похожее (с 4.9.9.3)

Кнопка «🎛 Собрать подборку» в разделе музыки показывает жанры и артистов
вашего хранилища, где треков хотя бы два, и собирает из них плейлист;
повторное нажатие пересобирает его, а не заводит второй.

Возможность «Музыка: данные из открытых баз» (`music_meta`, по умолчанию
выключена) после загрузки трека спрашивает MusicBrainz о жанре, если
в тегах его нет, и ListenBrainz о родственных артистах — подбор похожего
становится точнее. Всё — только внутри своего хранилища: общей
библиотеки нет. Выключено по умолчанию, потому что это запросы к чужим
сервисам с названием трека.

### Музыка в облаке (с 4.9.9)

Внешний носитель упирается в тот же сервер. Возможность **«Музыка
в облаке»** (`music_cloud`, по умолчанию выключена) переносит треки
в облако: рядом с ботом поднимается `rclone serve webdav`, бот кладёт
и забирает файлы по HTTP, а на устройстве остаётся кэш последних треков.

Настройка облака делается на сервере один раз:

```bash
# выбрать провайдера и войти (Яндекс.Диск, Mail.ru, S3, WebDAV — 70+ вариантов)
docker run --rm -it -v ~/radar_bot/data/rclone:/config/rclone rclone/rclone config
```

Дальше — профиль в `docker-compose.yml` и три строки в `.env`:

```bash
MUSIC_CLOUD_REMOTE=имя_из_rclone_config:музыка
MUSIC_CLOUD_URL=http://radar_rclone:8080
# логин и пароль нужны, только если запускать rclone с --user/--pass
```

```bash
docker compose --profile cloud up -d
```

Потом включить тумблер «Музыка в облаке» в `/features`. Проверить, что
хранилище отвечает и сколько в нём места, — `/doctor`.

Что важно понимать:

- **порт WebDAV наружу не публикуется** и не должен: там нет шифрования,
  и слушать он обязан только внутреннюю сеть Compose;
- **отказ облака не теряет трек** — он остаётся на устройстве, и бот
  об этом прямо говорит. Место в этом случае тратится своё;
- **кэш занимает до 256 МБ** и вытесняет то, к чему дольше не обращались;
  потерять его можно без последствий — исходники в облаке;
- **отдача трека идёт через чужую сеть**, поэтому она медленнее, чем
  с диска. Оповещения этим путём не ходят вовсе: музыка и мониторинг
  не делят ни очередь, ни канал;
- **пережатие («🗜 Сжать») заменяет файл и в облаке**, иначе место
  освобождалось бы только на диске.

Почему WebDAV, а не подключение облака каталогом: `rclone mount` дал бы
работу без единой правки в боте, но требует FUSE внутри контейнера
(`--cap-add SYS_ADMIN`) — заметно более широкие права у процесса,
который ходит в интернет за новостями. Сто строк своего клиента дешевле.


#### Подключение облака из панели (с 4.9.9.1)

Раздел **«Облако»** в панели (пункт в «Медиа») заводит и убирает хранилища
сам — `rclone config` на сервере больше не обязателен. Для этого rclone
поднимается с управляющим API, а панель обращается к нему по сети:

```bash
# в .env
RCLONE_RC_URL=http://radar_rclone:5572
RCLONE_RC_USER=radar
RCLONE_RC_PASS=придумайте_свой
```

Профиль `cloud` запускает rclone уже с нужными ключами. Порт управления
наружу не публикуется — доступ только из внутренней сети Compose.

Прямо из панели заводятся **WebDAV, S3, SFTP и FTP** — всё, чему хватает
адреса, логина и пароля. Там же видно, отвечает ли хранилище боту, сколько
в нём места и сколько весит кэш на устройстве.

**Чего панель не может и не сможет.** Яндекс.Диск, Google Drive и Dropbox
входят через браузер: человек нажимает «разрешить» на странице провайдера,
и без этого токена не будет. Панель браузером не располагает, а терминала
в ней нет и не будет — это отдельное правило проекта. Для Яндекса проще
всего обойти это через WebDAV: адрес `https://webdav.yandex.ru` и **пароль
приложения** вместо основного. Для остальных остаётся `rclone authorize`
на любой машине с браузером.

Панель не выполняет команд на сервере: она вызывает чужой сервис
с закрытым списком действий — завести запись о доступе, убрать запись,
спросить об объёме.

## Проверка ссылок

Команда `/check` и кнопка «🔍 Проверить ссылку» в главном меню (флаг
`linkcheck`, по умолчанию выключен). Разбирает адрес на признаки фишинга:
подмена букв под бренд, чужой бренд в домене, учётные данные перед `@`,
исполняемые схемы и файлы, слова-приманки, сокращатели. Сетевые
проверки — цепочка редиректов, возраст домена и регистратор (RDAP), срок сертификата,
базы Google Safe Browsing (ключ — в разделе ключей, группа «Защита»;
без него сетевая часть работает частично; отключаются переменной
`LINKCHECK_NET=0`).

Бесплатно **200 проверок в сутки** всем, подписчикам — без дневного
предела. Частота — `LINKCHECK_RATE_LIMIT` проверок в минуту (по умолчанию
5, подписчиков не касается).

Вывод перечисляет признаки с весами и **никогда не говорит «ссылка
безопасна»** — отсутствие признаков не гарантия. Проверяйте источники
через официальные каналы.

## Модерация групп

Флаг `moderation`, по умолчанию выключен. Бот добавляется в группу
и получает права администратора — **удаление сообщений** и **блокировку
участников**; без них он один раз скажет об этом в чат и работать
не будет. Менять privacy mode у @BotFather не нужно: администратор
получает все сообщения и так.

Что делает: удаляет спам и подозрительные ссылки (той же проверкой, что
и `/check`), запрещает ссылки новичкам первые сутки, ведёт лестницу
«предупреждение → мут → бан», встречает новичков кнопкой «я не бот»
(до нажатия — тишина), держит антифлуд и список стоп-слов, убирает
служебные сообщения о входе и выходе.

Администраторам чата в самой группе: `/warn`, `/mute`, `/ban`, `/unban`
ответом на сообщение и `/modstatus` — текущие настройки. Права
проверяются у Telegram, а не по ролям «Радара»: администратор группы
и администратор бота — разные списки. Самих администраторов чата бот
не модерирует.

Список чатов и тумблеры — в панели, раздел «Чаты», и в командной строке:

```bash
bash tools/radarctl.sh chats list
bash tools/radarctl.sh chats off -1001234567890
```

**Разделы для личной переписки в группах молчат.** Это отдельная правка
того же выпуска: раньше бот в группе отвечал каждому «Доступ закрыт»,
записывал участников в свои пользователи и отвечал ИИ на любой текст.

### Как добавить бота в группу

1. Группа → «Участники» → «Добавить» → найдите бота по имени.
2. Там же сделайте его **администратором** и включите права
   **«Удаление сообщений»** и **«Блокировка участников»**.
   Для кнопки перехода из бота пригодится ещё «Пригласительные ссылки» —
   но только если у группы нет ни публичного имени, ни уже созданной
   ссылки.
3. Напишите в группе `/modon` — чат появится в разделе «Чаты».

Privacy mode у @BotFather менять не нужно: администратор получает все
сообщения и так.

### Бот уже в группе

Ничего добавлять не надо — проверьте права администратора и напишите
в группе `/modon`. Отдельная команда нужна потому, что Telegram сообщает
боту только **об изменениях**: группы, куда его добавили раньше, сами
о себе не заявят никогда. `/modoff` выключает модерацию в этом чате,
`/modstatus` показывает текущие настройки.

**Тем, кто уже сидит в группе, бот ничего не пишет.** Приветствие
и проверка «я не бот» достаются только тем, кто войдёт после включения.

### Переход в группу из бота

Раздел «Чаты» (кнопка в «Управлении») показывает все группы; нажатие
открывает саму группу. Ссылка выбирается так: публичное имя `@name`,
затем **уже существующая** ссылка владельца, и только если нет ни того
ни другого — бот создаёт свою. Прежнюю ссылку он при этом не отзывает:
иначе у всех, кому её раздали, она перестала бы работать.

### Объявление в группу от имени бота (с 4.9.8.14)

Флаг `chat_post`, по умолчанию выключен. В разделе «Чаты» рядом с каждой
группой появляется кнопка ✍️ — **только у суперадминистратора**: сообщение
уходит от имени бота, и для участников это голос системы, а не частное
письмо.

Порядок такой: кнопка → текст (жирный, курсив и ссылки сохраняются, как
набрали) → показ того, как объявление увидят в группе → подтверждение →
отправка. Шаг с показом убрать нельзя: опубликованное в чужой группе
не отзывается.

До отправки проверяются длина (предел 3500 символов) и разметка:
незнакомый Telegram тег означал бы не «объявление без курсива», а
объявление, не ушедшее совсем. Черновик живёт десять минут — забытый
не уйдёт в группу назавтра. Если отправить не удалось, бот называет
причину: обычно бота выгнали, сняли права или в группе запрещены
сообщения от ботов.

### Ссылка приглашения в чат (с 4.9.9.1)

Бот умеет найти ссылку сам: публичное имя группы, ссылка владельца, своя
созданная. Но есть случаи, где автоматика не годится — закрытый чат
со вступлением по заявке, ссылка с ограничением по времени или числу
переходов, приглашение, которое владелец выдал отдельно.

Тогда её задаёт **суперадминистратор**, и она становится главной, а не
запасной. Двумя способами, на выбор:

* **в боте** — раздел «Чаты», кнопка ➕ рядом с группой (🔗, если ссылка
  уже задана). Прислать ссылку сообщением; `-` снимает её обратно;
* **в панели** — раздел «Чаты», колонка «Приглашение»: поле правится там
  же, где показано. Пустое поле снимает свою ссылку.

С 4.9.9.2 такие чаты видны **всем пользователям**: в главном меню
появляется кнопка «💬 Наши чаты» с кнопкой на каждый. Показываются только
чаты со ссылкой, заданной руками: закрытая группа, куда бота просто
добавили модерировать, открытой для всех от этого не становится.

После сохранения кнопка перехода в списке чатов ведёт по ней. Годится
любой адрес вида `https://t.me/…`.

### Объявление в группу из панели (с 4.9.9.1)

То же, что кнопка ✍️ в боте, и тем же путём в два шага: выбрать группу,
набрать текст, увидеть, как его прочитают участники, и только потом
отправить. Показ убрать нельзя: опубликованное в чужой группе
не отзывается.

Разметка задаётся тегами — `<b>`, `<i>`, `<a href=…>`. Незнакомый Telegram
тег страница отклонит до отправки: это означало бы не «объявление без
курсива», а объявление, не ушедшее совсем.

### Мессенджер MAX (с 4.9.9.4) ⚠️ не проверено в работе

Возможность «Мессенджер MAX» (`platform_max`, по умолчанию выключена).
Адаптер написан по документации [dev.max.ru](https://dev.max.ru/docs-api/):
опрос событий, отправка сообщений, ответ на нажатия кнопок, пределы
площадки и ограничитель в 30 запросов в секунду. Токен задаётся
переменной `MAX_BOT_TOKEN`, адрес — `MAX_API_URL`.

**Ни один запрос не выполнялся против живого сервера.** Токен в MAX
выдают только верифицированным юрлицам РФ, а без токена нельзя проверить
ни адрес, ни имена полей, ни формат ответов.

Что бот умеет в MAX сейчас: `/start`, `/help`, `/status` и честный ответ
на остальное. **Оповещения отсюда не рассылаются:** локации, роли
и подписка привязаны к учётной записи Telegram, а без подтверждённого
адреса тревога не отправляется. Полное ядро в MAX не переносится, пока
площадка не проверена хотя бы одним живым запросом.

### Discord (с 5.5) ⚠️ не проверено в работе

Флаг `platform_discord`, по умолчанию выключен. Discord здесь — **канал
сообщества**, а не оповещения по адресам: без подтверждённой географии
тревога не отправляется, а адреса живут в Telegram.

- слеш-команды `/about`, `/status`, `/summary`, `/help`;
- суточная сводка в канал `DISCORD_CHANNEL_ID` в `DISCORD_SUMMARY_TIME`
  (по умолчанию 20:00): сколько событий было по категориям и сколько
  отбоев — без адресов, городов и текста;
- сообщение в канал, когда мониторинг замолчал и когда поднялся снова.

Адаптер написан на `aiohttp` без `discord.py`: REST и Gateway
(WebSocket) с сердцебиением, восстановлением сессии и соблюдением
пределов площадки. Протокол сверен с исходниками `discord.py`, транспорт
проверяется по настоящему WebSocket через эмулятор
(`tools/discord_http_check.py`, шаг CI). С живым Discord не работал.
Настройка — раздел 15 в [docs/API_SETUP.md](docs/API_SETUP.md).

### ВКонтакте и копии тревог (с 5.6) ⚠️ не проверено в работе

Флаг `platform_vk`, по умолчанию выключен. Бот сообщества ВКонтакте
работает через Bots Long Poll API — входящий адрес не нужен.

**Привязка.** В Telegram: «⚙️ Оповещения» → «🔗 Привязать ВК или MAX»
(или `/link`) — бот выдаёт шестизначный код на 10 минут. Код отправляют
боту во ВКонтакте или в MAX, и с этого момента **тревоги по адресам
приходят и туда** — копией того, что пришло в Telegram. Адреса
и настройки остаются в Telegram: география подтверждена там, поэтому
правило «без подтверждённой географии тревога не отправляется» соблюдено.

- копия уходит фоновой задачей: Telegram не ждёт её, а сбой ВК или MAX
  не задерживает и не роняет цикл оповещений;
- код выдаёт только Telegram, где у человека адреса: чужие тревоги
  к себе не направить, зная чужой id ВК; перебор ограничен пятью
  неверными кодами за 10 минут;
- `/unlink` в ВК или MAX либо кнопка в Telegram снимают привязку.

Viber и WhatsApp не подключаются: у Viber с 2024 года боты только
по договору и за 115 € в месяц плюс оплата каждого сообщения, у WhatsApp
с июля 2025 оплачивается каждое шаблонное сообщение и нужна верификация
бизнеса в Meta — подробности в [дорожной карте](docs/ROADMAP.md).
Настройка ВК — раздел 16 в [docs/API_SETUP.md](docs/API_SETUP.md).

## Язык интерфейса

Бот спрашивает язык при первом обращении — и у новых людей, и у тех, кто
пользовался ботом до появления выбора. Сменить можно позже из меню
(«🌍 Язык»).

Словарь — `radar/i18n.py`; непереведённая строка возвращает русский
вариант, а не служебный ключ.

С 4.7.6 **на английский переведено всё, что доступно обычному
пользователю:** главное меню, оповещения, погода текстом и картинкой
(включая розу ветров и фазы луны), новостные подборки, SOS, журнал,
загрузка видео, экран «Оповещения» целиком, «Предложить источник»,
`/help` и названия ролей.

На русском намеренно остаются экраны суперадминистратора — ключи,
управление ИИ, сеть, копии, журналы, редактор партнёрских проектов.
Их читает только владелец системы, и перевод удвоил бы поддержку
без единого читателя.

## Обновление с прежних версий

**С 4.6.1 поддержка формата базы 3.3.5 прекращена.** Импортёр `db.json`
удалён: код миграции с версии почти двухлетней давности никем не проверялся,
и держать его дальше означало возить с собой непроверенный путь через
все сборки.

### Полный путь обновления

Найдите свою версию в левом столбце и пройдите шаги сверху вниз.

| Откуда | Что делать |
|---|---|
| **2.x** (монолитный `bot.py`, `data/db.json`) | 1. Обновиться до **3.3.5** и дать боту один раз запуститься — он приведёт `db.json` к нужному виду.<br>2. Обновиться до **4.6.0** — база перенесётся из JSON в SQLite или PostgreSQL.<br>3. Обновиться до текущей версии. |
| **3.0 — 3.3.5** (`data/db.json`) | 1. Обновиться до **4.6.0** — на этой версии импортёр `db.json` работает в последний раз.<br>2. Убедиться, что рядом появился `db.json.migrated` и бот видит пользователей.<br>3. Обновиться до текущей версии. |
| **4.0 — 4.6.0** | Обновиться напрямую: `sudo bash install.sh`. |

Промежуточные версии берутся из релизов на GitHub. Пропускать шаг 4.6.0
при переходе с 3.x нельзя — без него данные останутся в JSON, а новый код
их не прочитает и молча начнёт с пустой базы.

### Что можно делать в панели

Панель повторяет права бота, а не расширяет их: роль означает в обоих
местах одно и то же.

- **Модератор** правит список источников — добавляет и удаляет
  Telegram-каналы, RSS-ленты и сообщества ВКонтакте. Разбор ссылок общий
  с ботом (`radar/sourceedit.py`), поэтому `@name`, `t.me/name` и голое
  имя дают один результат в обоих местах. Очередь предложений остаётся
  в боте: там вместе с решением уходит ответ приславшему.
- **Модератор** правит часовой пояс и время погоды у пользователя —
  когда это делает не сам человек, а администрация по его просьбе.
- **Суперадминистратор** включает и выключает возможности.
- **Суперадминистратор** заводит и правит партнёрские проекты — название,
  ссылку, описание, значок, порядок, видимость и промокоды: всё то же, что
  в боте. Заводить проект с описанием в переписке неудобно, а в панели
  поле описания видно целиком.
- **Суперадминистратор** задаёт ключи ИИ и токены сервисов, а во вкладке
  «Файлы» видит раздачу целиком: кому выдана ссылка, есть ли у человека
  подписка, забрали файл или он ещё ждёт, сколько осталось до сгорания.
  Ссылку можно отключить досрочно.

Панель работает в светлой и тёмной темах — переключатель в шапке, выбор
запоминается в браузере, по умолчанию берётся системный.

**С телефона панель открывается как есть.** Разделы уезжают отдельной
строкой во всю ширину, кнопки и ссылки рассчитаны на палец, широкие
таблицы прокручиваются вбок, а список пользователей на узком экране
разворачивается в карточки «поле: значение». Оформление при этом не
урезается: дождь «Матрицы» и уголки «Реактора» остаются и на телефоне.

**Ключи вводятся, но не показываются.** Существующее значение видно только
маской вида `AIza…9kQw`: проверить, тот ли ключ вставлен, по ней можно,
а увести — нет. Доступ к перехваченной сессии панели не должен означать
доступ ко всем ключам сразу. Полное значение остаётся в `.env` на сервере.
В журнал панели пишется имя изменённого ключа и никогда значение — журнал
читается в самой панели.

Формы защищены скрытым токеном, привязанным к сессии, вдобавок к
`SameSite=Lax` у cookie: одна мера задаётся одной строкой кода, и её
правка молча сняла бы защиту.

### Веб-панель по домену

После получения сертификата остаётся шаг, который делается **в Telegram,
а не на сервере**: привязать домен к боту.

1. Откройте **@BotFather**
2. Команда `/setdomain`
3. Выберите своего бота
4. Пришлите адрес панели: `https://ваш-домен`

Без этого виджет входа показывает только «Bot domain invalid», и по этой
надписи догадаться, что делать, невозможно. Адрес должен совпадать точно —
со схемой `https://` и без пути в конце.

**По IP-адресу вход через Telegram не работает вовсе:** виджет принимает
только домены. Это ограничение Telegram, а не настройка панели.


### Темы панели

Кнопка в шапке переключает оформление по кругу: **светлая → тёмная →
«Матрица» → «Реактор»**. Выбор запоминается в браузере, у каждого
администратора свой.

«Матрица» — зелёный терминал с дождём символов и командной строкой
в заголовке. «Реактор» — приборная панель: сетка, уголки-скобки
у карточек, свечение показателей.

Оформление ничего не запрашивает у сервера и не подключает внешних
шрифтов: панель на машине без выхода в интернет открывается так же.
Анимации выключаются системной настройкой «меньше движения» и гаснут
в фоновой вкладке.

### Обновление из панели

Раздел «Обновление» у суперадминистратора скачивает с GitHub установщик
последнего выпуска, проверяет его и запускает: снимок перед заменой,
сборка образа, перезапуск. Скачанный установщик заменяет собой
`install.sh` в каталоге установки. Если GitHub недоступен, причина
появится в журнале на той же странице.

**До 4.9.8.9 кнопка ставила ту же версию, что стояла:** она запускала
`install.sh`, уже лежавший на сервере, а он несёт код внутри себя.
Исправление живёт в коде бота, поэтому сервер на 4.9.8.8 и старше один
раз нужно обновить руками, скачав свежий установщик:

```bash
cd ~/radar_bot
curl -fsSLo install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
bash install.sh
```

Дальше кнопка в панели работает сама.

### Командная строка

Всё, что умеет панель, работает и из консоли — обёртка лежит рядом
с установкой:

```bash
bash tools/radarctl.sh --help
bash tools/radarctl.sh sources list
bash tools/radarctl.sh features on digest
bash tools/radarctl.sh backup create
bash tools/radarctl.sh rustdesk connections --json
bash tools/radarctl.sh doctor --quick
```

Команды бота выполняются внутри контейнера (там база и `.env`), команды
установки — на хосте: `update`, `restore`, `wipe`. У читающих команд есть
`--json`, а разрушающие без `--yes` ничего не делают и возвращают код `2`,
отличный от кода ошибки — чтобы `cron` не путал «не подтвердили»

### Удаление установки

Для покинутого сервера после переезда — стирает контейнеры, образ и
каталог целиком, вместе с базой, ключами, копиями и журналами:

```bash
bash tools/radarctl.sh wipe          # спросит подтверждение
bash tools/radarctl.sh wipe --yes    # без вопросов
```

То же есть в панели — «Обслуживание» → «Удаление», за отдельной
возможностью `panel_wipe` (по умолчанию выключена) и с подтверждением
словом, а не кнопкой. Панель в процессе перестаёт отвечать: она живёт
в том же контейнере, который удаляется.

**Чего удаление не делает:** оно не отзывает выданные токены. Если сервер
уходит из ваших рук — смените токен бота у @BotFather и ключи ИИ, они
были в `.env`. И помните, что на флеш-карте удаление файла не стирает
данные физически: плату надёжнее перепрошить. Шаги видны прямо в панели — установщик
пишет пошаговый журнал в `data/logs`, и страница читает свежий, обновляясь
сама, пока идёт работа. На шаге пересборки панель ненадолго становится
недоступна: перезапускается сам контейнер бота, — после возврата страница
дочитает журнал до конца.

**Возможность `panel_update` по умолчанию выключена, и это не осторожность
ради галочки.** Чтобы контейнер мог обновить систему, ему нужен сокет
Docker, а сокет Docker внутри контейнера равносилен правам root на хосте:
тот, кто получит доступ к панели, получит и сервер. Включайте, понимая
эту цену; панель при этом не выполняет произвольных команд — только один
заданный сценарий, терминала сервера в ней нет и не будет.

### Переезд на другой сервер

На **старой** машине — одна команда, без полной установки:

```bash
curl -fsSLo radar-install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
sudo bash radar-install.sh --migrate
```

Установщик соберёт копию (база, `.env`, файлы данных) и спросит, как
передать её на новую машину. **Два варианта:**

**1. Вручную — надёжный путь.** Файл копии переносится любым способом
(scp, флешка), установщик на новой машине разворачивает его сам:

```bash
# на старой машине:
scp /root/radar_bot/backups/radar-backup-ГГГГММДД-ЧЧММСС.tar.gz пользователь@новый-сервер:~/

# на новой машине (нужен Docker: curl -fsSL https://get.docker.com | sh):
curl -fsSLo radar-install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
sudo bash radar-install.sh --restore
```

`--restore` без имени возьмёт архив из текущего каталога: положите файл
рядом с установщиком и запустите.

**2. Одноразовой ссылкой — ⚠️ путь ещё не проверен на живом переезде.**
Установщик склеит копию с самим собой в один самодостаточный файл,
поднимет одноразовую раздачу и напечатает две команды для новой машины:

```bash
curl -fsSLo radar-restore.sh http://АДРЕС-СТАРОГО-СЕРВЕРА:8899/ТОКЕН
sudo bash radar-restore.sh
```

Скачанный файл содержит и код бота, и данные — GitHub новому серверу не
нужен. Пока ссылка жива, установщик ждёт скачивания с обратным отсчётом;
Ctrl+C отменяет, закрытие терминала не прерывает. Ссылка срабатывает один
раз и живёт 30 минут, а внутри — токен бота и пароли, так что ссылку
никому не пересылайте; **порт 8899 должен быть проброшен на роутере
старого сервера на саму машину** — без проброса новый сервер не
подключится, и тогда проще вернуться к ручному варианту.

В обоих случаях дальше идёт обычная установка поверх данных копии:
дамп заливается **до** старта бота, а после запуска система пересчитывает
пользователей, локаций и источники и сообщает, сошлось ли.

**Старый бот не выключается автоматически.** Два экземпляра с одним токеном
отбирают друг у друга обновления, поэтому пока идёт проверка, новый бот
может отвечать через раз — это нормально. Убедитесь, что новый работает,
и только потом остановите старый:

```bash
cd /root/radar_bot && docker compose down
```

Если в копии дамп PostgreSQL, а на новой машине выбрана SQLite, залить его
нельзя — это разные диалекты SQL. Установщик скажет об этом прямо: выберите
PostgreSQL либо переносите файл `data/radar.db` руками.

### Полное удаление

Флаг `--uninstall` установщика останавливает и удаляет контейнеры и образ,
**сохраняя** базу и настройки. Чтобы убрать систему целиком — база, `.env`,
копии, журналы, каталог установки:

```bash
curl -fsSLo uninstall.sh https://raw.githubusercontent.com/Chistovik92/radar/main/tools/uninstall.sh
bash uninstall.sh
```

Скрипт самодостаточен: работает и на сломанной установке, сеть
и репозиторий не нужны. Спрашивает явное «да» и перед удалением умеет
снять последнюю копию (без кэша видео и журналов). Для автоматизации —
флаг `--yes`; нестандартный каталог — `RADAR_HOME=/путь`.

### Выбор устанавливаемой версии

По умолчанию ставится код из `main` — самый свежий, независимо от того,
оформлен он релизом или нет.

```bash
sudo bash install.sh --versions          # что вообще доступно
sudo bash install.sh --version=v4.6.1    # поставить конкретный релиз
```

Установка более старого релиза **и есть откат**. Он не запрещён и не
требует подтверждения: если новая версия сломалась, вернуться нужно
немедленно, а не доказывать установщику, что вы понимаете последствия.
Снимок перед перезаписью снимается в любом случае.

Если установка сорвётся, среди предложенных действий появится пункт
«поставить предыдущий релиз с GitHub» — на случай, когда сломан сам код
и снимок не помогает.

### Перед любым обновлением

```bash
sudo bash install.sh --backup
```

Копия кладётся рядом с установкой. Если обновление сорвётся, установщик
сам предложит восстановиться; вручную это делается так:

```bash
sudo bash install.sh --rollback
```

Схема базы проверяется на совместимость при каждом старте: если она осталась
от версии с ошибкой, таблицы пересоздаются с сохранением пользователей,
локаций и источников.

## Ограничения

- Читаются только **публичные** веб-превью каналов (`t.me/s/<канал>`); закрытые недоступны.
- Nominatim ограничивает геокодирование одним запросом в секунду — при массовом добавлении
  локаций стоит поднять свой инстанс.
- JSON-хранилища хватает на сотни пользователей; дальше нужен SQLite или Postgres.
- Классификация вероятностная: возможны ложные срабатывания и пропуски.
  **Система не заменяет официальные каналы оповещения.**

## Журналы

Всё пишется в `data/logs/`: журнал бота с ротацией и отдельный файл на каждый
запуск установщика с датой в имени. Суперадминистратор управляет ими прямо
в боте — раздел «📋 Журналы» или команды `/logs`, `/logtail`, `/logclear`:
просмотр последних строк, выгрузка отдельных файлов и архивом, очистка.

Журналы контейнеров Docker собираются на сервере:

```bash
bash ~/radar_bot/collect-logs.sh
```

Скрипт складывает журналы установки, бота, обоих контейнеров и сводку
о системе в один архив. Секреты из `.env` в него не попадают.

## Загрузка видео по ссылке

Функция под флагом `media_download` (по умолчанию выключена): пришлите ссылку —
бот покажет доступные качества с размерами и отправит файл. Поддерживаются
YouTube, VK Видео, RuTube, Одноклассники, Дзен, TikTok, X, Instagram и другие
площадки, которые умеет yt-dlp.

Предел отправки у обычного Bot API — 50 МБ. Чтобы поднять его до 2 ГБ,
запустите собственный Bot API Server:

```bash
# в .env: TELEGRAM_API_ID, TELEGRAM_API_HASH с my.telegram.org
#         TELEGRAM_API_SERVER=http://telegram-bot-api:8081
docker compose --profile media up -d
```

Скачивайте только то, на что у вас есть право: правила площадок и авторские
права функция не отменяет.

## Крупные файлы по ссылке

Telegram принимает от ботов не больше 50 МБ. Раньше на этом разговор
заканчивался: «выберите качество ниже — или поднимите собственный Bot API
Server». Оба совета верны и оба неуместны, когда качества ниже нет,
а второй сервер ради одного файла никто поднимать не станет.

Если задан `SHORT_BASE_URL` — внешний адрес, на котором открыта панель, —
файл отдаётся ссылкой: он не отправляется в мессенджер вовсе, человек
скачивает его сам. Предел Telegram при этом не обходится, а объезжается.

Ссылку получает только пользователь бота: её выдаёт бот в переписке.
Сама ссылка — секрет, и кто её получил, тот скачает: проверить учётную
запись Telegram при обычном запросе из браузера невозможно. Поэтому имя
файла непредсказуемо (32 знака), ссылка живёт сутки, а раздача целиком
ограничена бюджетом места — забитый диск остановил бы оповещения.

Просроченное и лишнее сверх бюджета убирается раз в цикл, вместе
с остатками прерванных загрузок.

## Кнопка SOS

Отдельная кнопка в главном меню: бот запрашивает геопозицию и отправляет её
доверенному контакту вместе с просьбой о помощи — координаты, разобранный
адрес, время и ссылка на карту, плюс отдельным сообщением сама геоточка.
Сигнал повторяется каждые 10 минут, пока отправитель не нажмёт «Я в порядке».

Важное ограничение платформы: Telegram не даёт боту написать первым тому,
кто с ним не общался. Поэтому доверенный контакт получает ссылку-приглашение
и должен один раз нажать «Старт». Пока он этого не сделал, сигнал уходит
администраторам системы.

Включается флагом `sos` в `/features`. **Бот не заменяет экстренные службы** —
при угрозе жизни звоните 112.

## Подписка

Подписка одна на бота. Она открывает сразу несколько вещей:

- новостные подборки по всем тематикам;
- загрузку видео без дневного предела;
- адрес и ключ своего сервера RustDesk, если раздел включён (см. ниже).

**Раздельно эти части не продаются.** Модель под ними и раньше была одна —
оплата любой открывала обе, — но человек видел два предложения и разумно
заключал, что покупать надо оба. Продавать дважды одно и то же ощущение
нельзя, поэтому вход теперь один: `/subscription` или кнопка из раздела
видео.

**Пробный период — 7 дней**, один раз на человека. Он предлагается сразу,
а не после отказа от покупки: иначе увидят его только те, кто дошёл
до отказа.

**Оповещения об опасности бесплатны всегда** и от подписки не зависят.
Это правило проекта, а не текущая настройка.

Правка тарифов — в управлении, кнопка «💳 Подписка».

## RustDesk

Свой сервер удалённого доступа (hbbs/hbbr) рядом с ботом — флаг `rustdesk`,
по умолчанию выключен. Установщик разворачивает контейнеры сам (профиль
`rustdesk` в `docker-compose.yml`) и при повторном запуске сверяет, что
под ожидаемым именем именно `rustdesk-server`, а не что-то чужое.
Внешний адрес спрашивается только один раз: если сертификат панели уже
получен через `tls.sh`, установщик предлагает тот же домен — Enter
соглашается.

Раздел в меню бота: адрес и ключ для настройки клиента — подписчикам
и администрации; число подключений прямо сейчас — администрации;
запуск, остановка и перезапуск — суперадминистратору. Экран с адресом
и ключом сразу показывает шаги настройки клиента и ссылку на его
скачивание. То же самое (адрес и ключ, подключения, управление) есть
и в веб-панели — раздел «RustDesk» в «Обзоре», только суперадминистратору.
Подробности развёртывания и переменные `.env` — в
[docs/API_SETUP.md](docs/API_SETUP.md).

## VPN (с 5.0) ⚠️ не проверено на живых панелях

Выдача доступа к VPN из бота — флаг `vpn`, по умолчанию выключен.
С 5.0.1 панелей может быть **несколько сразу, в том числе разных**:
до шести слотов (`VPN1_*` … `VPN6_*`), у каждого свой вид, адрес и вход.
Поддерживаются десять панелей через один внутренний слой
(`radar/vpnpanels.py`):

| Панель | Вход | Что получает человек |
|---|---|---|
| **3x-ui** 2.x и 3.x | токен API или логин с паролем (в 3.x — с CSRF) | подписку |
| **x-ui** (alireza0) | логин с паролем | подписку |
| **s-ui** | токен API | подписку |
| **Marzban** | токен или логин с паролем | подписку |
| **PasarGuard** | ключ API или логин с паролем | подписку |
| **Marzneshin** | токен или логин с паролем | подписку |
| **Remnawave** | токен API | подписку |
| **Hiddify** | ключ API (uuid администратора) | страницу подключения |
| **Outline** | apiUrl + отпечаток сертификата | ключ `ss://`, без сроков |
| **wg-easy** | логин с паролем | одноразовую ссылку на файл WireGuard, без предела трафика |

Не поддерживаются намеренно: AmneziaVPN (управляется только по SSH,
HTTP API для ключей у неё нет) и голый Xray или sing-box без панели
(они не хранят пользователей).

**Выдачу полностью контролирует суперадминистратор.** Без его решения
доступа не получает никто, включая администраторов:

- человек открывает «🔐 VPN» и отправляет заявку — письмо приходит
  только суперадминистратору;
- тот отмечает, на какие панели выдать, и нажимает «Выдать» — ссылки
  приходят человеку в личку, по одной на панель;
- в разделе видны заявки, выданные доступы по каждой панели, продление
  на `VPN_DAYS` дней, выключение, отзыв и проверка всех панелей разом.

Проверка роли стоит не только на кнопках, но и в самой логике выдачи:
вызов от имени кого-то, кроме суперадминистратора, отклоняется.

Обращения к разным панелям идут **параллельно**, и отказ одной
не задерживает и не ломает остальные: выдача на три панели, из которых
одна недоступна, выдаст на две и честно скажет про третью.

Продление и повторная выдача возвращают **тот же ключ**: имя записи
в панели выводится из идентификатора пользователя. Окончание срока
отключает доступ силами самой панели — бот ничего не опрашивает
по расписанию, и цикл оповещений с панелями не пересекается.

Ссылки в базу не пишутся, в журнал не попадают ни они, ни UUID, ни токены.
Платежей нет. Настройка — раздел «VPN» в
[docs/API_SETUP.md](docs/API_SETUP.md).

### Продажа по тарифам (с 5.0.2) ⚠️ не проверено с настоящими платежами

Флаг `vpn_sales`, по умолчанию выключен, — продажи включает только
суперадминистратор. Тарифы — строка `VPN_PLANS` в разделе ключей:
`дни:трафикГБ:устройства:цена` через точку с запятой, например
`30:0:3:199; 90:0:3:499` (0 — без предела). Валюта — `VPN_CURRENCY`,
по умолчанию RUB; панели для продажи — `VPN_PLAN_SLOTS`.

Оплату принимает сменный провайдер (`PAY_PROVIDER`):

- **manual** — бот денег не принимает: человек платит так, как указано
  в `PAY_MANUAL_NOTE`, а суперадминистратор подтверждает оплату кнопкой.
  Работает без регистрации где-либо;
- **cryptopay** — Crypto Pay (@CryptoBot): счёт в Telegram, оплата
  криптовалютой, бот сверяет состояние счёта по кнопке «Я оплатил».
  Регистрации продавца не требует.

Оплата продлевает **тот же** ключ и прибавляет дни к оставшимся.
Двойное нажатие «Я оплатил» не выдаёт доступ дважды. Если панель
не ответила, заказ остаётся оплаченным, а суперадминистратор получает
кнопку «Повторить выдачу». Предел устройств действует на 3x-ui, x-ui
(`limitIp`) и Remnawave (`hwidDeviceLimit`); на остальных панелях его нет.

Комиссию Crypto Pay, лимиты и условия вывода код не проверяет —
посмотрите их в самом @CryptoBot до включения продаж. Telegram Stars
для продажи VPN не используются: они для цифровых товаров внутри
Telegram. Доход облагается налогом независимо от канала — это решение
автора, а не кода. Оповещения об угрозах этим не затрагиваются: они
бесплатны всегда.

**Как проверить на своём сервере:**

```bash
python -m radar vpn check            # все панели: отвечает ли, принят ли вход
python -m radar vpn selftest --yes   # полный круг на тестовой записи radar_selftest
```

`selftest` заводит в каждой панели запись `radar_selftest`, проверяет
по ответу панели срок, выключение, включение и ссылку и оставляет запись
выключенной. Клиенты сверены с исходным кодом панелей и прогнаны
по HTTP через их эмуляторы (`tools/vpn_http_check.py`, шаг CI), но
с настоящими панелями не работали ни разу — `selftest` и есть первая
такая проверка.
