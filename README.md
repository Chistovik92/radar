# Система «Радар» v4.9.4.1

[English version](README.en.md)

Telegram-бот, который следит за городскими угрозами и авариями ЖКХ по вашим адресам.
Сообщения публичных каналов служб ЖКХ, МЧС, администраций города, района и области,
а также RSS-ленты СМИ разбирает ИИ Google Gemini, после чего события сопоставляются
с сохранёнными локациями.

## Установка

Одной командой на чистой Debian или Ubuntu:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh)
```

Установщик на английском:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh) --lang=en
```

Надёжнее — скачать скрипт заранее и запустить файлом. При обрыве связи
подстановка `<(curl ...)` отдаёт скрипт не целиком, и хотя установщик это
переживёт (тело обёрнуто в функцию, неполный файл просто не выполнится),
скачанный файл можно перезапустить, не выкачивая заново:

```bash
curl -fsSLo radar-install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
bash radar-install.sh
```

Скрипт сам создаст `~/radar_bot`, развернёт исходники, спросит токены, соберёт Docker-образ
и запустит контейнер. Повторный запуск той же команды обновляет бота: база `data/db.json`
и `.env` сохраняются.

Установщик проверяет компоненты системы, при необходимости обновляет пакеты
и образы Docker, диагностирует предыдущую установку и **спрашивает, как
поступить**: обновить поверх, переустановить, начать с чистого листа или
только снять копию. Если бот падал, установщик разбирает лог, называет
вероятную причину и подсказывает подходящий вариант — но выбор остаётся
за вами. Перед запуском бота выполняется диагностика внутри контейнера;
при ошибке бот не стартует, а вы получаете отчёт. Весь ход работы пишется
в `~/radar_bot/installer_log.txt`.

Флаги: `--backup` (снять копию и выйти), `--reset` (полный сброс: копия,
удаление базы, установка с нуля), `--recreate-env` (перезаписать настройки),
`--reinstall` (принудительная полная переустановка), `--skip-updates`
(не обновлять пакеты системы),
`--no-cache` (пересборка без кэша), `--logs` (показать логи),
`--rollback` (вернуть предыдущую версию из снимка),
`--uninstall` (снести контейнеры и образ, данные остаются), `--version`, `--help`.

Перед каждым обновлением установщик сохраняет снимок текущей установки.
Если новая версия не запускается, он предлагает откатиться на предыдущую
или поставить проверенную 3.3.5.

Установка из клона репозитория:

```bash
git clone https://github.com/Chistovik92/radar.git && cd radar
cp .env.example .env && nano .env      # задайте DB_PASSWORD (без символа $)
docker compose up -d --build
```

Поднимается один контейнер — `radar_container`. База по умолчанию SQLite:
файл `data/radar.db` рядом с ботом, отдельный сервер не нужен. Схема создаётся
при первом старте, данные версии 3.x из `data/db.json` переносятся автоматически.

Установщик спрашивает про базу при **любом** способе установки — в том числе
при обновлении поверх. Переключение между базами предупреждает, что данные
сами не переезжают, и просит подтверждения.

Для машины помощнее доступен PostgreSQL:

```bash
# в .env: DB_BACKEND=postgres, DB_PASSWORD=... (без символа $)
docker compose --profile postgres up -d --build
```

## Логика оповещений

| Тип события | Область | Формат сообщения |
|---|---|---|
| 🛸 БПЛА, ракетная опасность, воздушная тревога, работа ПВО | весь город | одно сообщение на город со списком всех совпавших локаций в нём |
| 🆘 МЧС: ЧС, штормовое предупреждение, эвакуация, пожары | город, либо адресно, если названы улицы | вместе с городскими или адресными |
| 🛠 ЖКХ: вода, свет, газ, отопление, порывы, ремонты | адресно — улица и дом | отдельное сообщение на группу локаций |
| 📵 «Белые списки» связи | весь город | автоматически добавляются к оповещению о БПЛА |
| ✅ Отбой опасности | весь город | отдельное сообщение с другим сигналом |
| 🌤 Погода | точка локации | отдельное сообщение, блок на каждую группу |

Дополнительные правила:

- Локаций у пользователя может быть **сколько угодно**.
- Локации ближе **1 км** друг к другу (связность транзитивная) объединяются в одну группу,
  и вся информация по ним выводится вместе. Радиус меняется через `CLUSTER_RADIUS_M`.
- В начале каждого сообщения перечислены **совпавшие локации**.
- О «белых списках» в пабликах почти не пишут — операторы вводят их молча.
  Поэтому предупреждение не ищется в новостях, а выдаётся автоматически вместе
  с оповещением о БПЛА или ракетной опасности: что перестанет работать,
  что продолжит и как связаться.
- Отбой опасности («опасность снята», «режим отменён») распознаётся отдельно
  и приходит спокойным сообщением с зелёным маркером, а не как новая тревога.
  К нему добавляется примечание, что «белые списки» могут отключить в ближайшее
  время — связь обычно восстанавливают не сразу.
- Новости из RSS-лент снабжаются ссылкой на источник.
- Дом сопоставляется точно, поддерживаются диапазоны вида `12-20`. Если дома не названы —
  срабатывает вся улица; если не названа улица, но назван район — сработает район;
  общегородская авария ЖКХ приходит на все локации этого города.

## Источники

Наборы по городам лежат в `radar/presets.py`: Саратов, Москва, Санкт-Петербург,
Казань, Самара плюс федеральные каналы, которые подключаются всегда. Какие
наборы включить при первом запуске — переменная `SOURCE_CITIES`.

Источники опрашиваются **параллельно**, но не более `SOURCE_CONCURRENCY`
одновременно (по умолчанию 6). До 4.7.7 обход был последовательным:
замер на боевом сервере показал 51 секунду на цикл при интервале 180 —
бот больше четверти времени ждал сеть, загрузив процессор на два процента.
Предел нужен, а не «все разом»: десятки одновременных запросов к `t.me`
с одного адреса выглядят как выкачивание, а расплачивается за это система
оповещения.

Списки устаревают молча: канал переименовали, ведомство ушло в другой мессенджер,
лента отдаёт 404. Проверка:

```bash
python3 tools/check_sources.py --all-presets
python3 tools/check_sources.py --file data/db.json --json report.json
```

Инструмент показывает дату последней публикации, помечает давно не обновлявшиеся
источники и отдельно — те, что упоминают переход в MAX.

То же самое доступно прямо в боте: кнопка «🔍 Проверить доступность» в панели
модератора или команда `/checksources`. По итогам можно одной кнопкой убрать
все недоступные источники.

Проверка не ограничивается кодом ответа: `t.me/s/<канал>` отдаёт 200 и для
закрытых, и для несуществующих каналов, поэтому проверяется наличие блоков
сообщений и дата последнего поста.

## Выгрузка и загрузка источников

В панели модератора есть кнопки «⬇️ Скачать список» и «⬆️ Загрузить список».
Выгрузка — версионированный JSON, который прочитают будущие версии бота:
формат помечен номером схемы, неизвестные поля игнорируются, отсутствующие
берутся по умолчанию. Загрузка принимает также простой список каналов текстом
и `db.json` от версии 3.x — так переносятся настройки со старой установки.

Выгрузка доступна модераторам, загрузка — администраторам.

## Погода

Сводка построена как в погодных приложениях: крупное текущее значение
с описанием, строка деталей (ощущается, ветер с порывами, влажность, давление),
почасовая таблица на 8 часов со столбиком температуры и вероятностью осадков,
прогноз на три дня, время восхода и заката. Почасовая часть выводится
моноширинным блоком, иначе колонки разъезжаются.

Для каждой группы локаций — отдельное сообщение.

## Часовой пояс

Города пользователей лежат в разных поясах, поэтому время у каждого своё.
Пояс выбирается в настройках оповещений и задаёт смысл трём вещам сразу:
тихим часам, времени погоды и доставке новостных подборок. Пока пояс
не выбран, берётся пояс сервера — как было до 4.8.4.4.

Подписи зависят от языка. По-русски отсчёт идёт от Москвы (`МСК+2`):
на русскоязычном пространстве о времени говорят именно так, и `UTC+5`
человеку из Саратова ничего не сообщает. По-английски — от Гринвича
(`UTC+5`).

Хранится смещение, а не название зоны. Плата за простоту — переход
на летнее время: смещение его не отслеживает. Для России это безразлично,
перевода стрелок нет с 2014 года; пользователю из Европы или США раз
в полгода придётся поправить выбор.

## ИИ и расход квоты

Используется Google Gemini (`google-genai`). Бесплатный тариф жёстко ограничен по числу
запросов (порядка 10 в минуту и несколько сотен в сутки), поэтому расход снижается
четырьмя способами:

1. **Предфильтр** — сообщения без ключевых слов ЖКХ/ЧС/БПЛА/связи вообще не уходят в модель;
   на городских каналах это отсекает большую часть ленты.
2. **Пакетный разбор** — до `AI_BATCH_SIZE` новостей в одном запросе.
3. **Кэш по хэшу текста** — одна новость анализируется один раз для всех пользователей,
   расход не зависит от числа подписчиков.
4. **Учёт RPM/RPD с резервом** — `AI_RESERVE` суточных запросов доступны только
   ИИ-ассистенту, фоновый анализ до них не дотягивается. После ответа 429 фон встаёт
   на паузу `AI_COOLDOWN`, а диалог продолжает работать.

Для разбора используется более дешёвая модель (`GEMINI_MODEL_ANALYSIS`,
по умолчанию `gemini-3.5-flash-lite`), для диалога — `GEMINI_MODEL`
(`gemini-3.6-flash`) с включённым поиском в интернете. Расход — `/quota`.

### Устойчивость к отключению моделей

Google выводит модели из обращения быстрее объявленных дат: `gemini-2.5-flash`
был закрыт для новых ключей задолго до официальной даты отключения, и запросы
стали возвращать 404. Поэтому имя модели не зашито намертво:

* при старте бот запрашивает `models.list` и выбирает первую доступную ключу
  модель из списка кандидатов;
* при ответе 404 модель понижается на лету, и запрос повторяется на следующей;
* `GEMINI_MODEL` в `.env` — приоритетный кандидат, а не жёсткое требование;
* команда `/models` (администратор) показывает выбранные и доступные модели.

Учтены и различия поколений: для 3.x не отправляются устаревшие `temperature`,
`top_p`, `top_k`, вместо `thinking_budget` используется `thinking_level`,
а история диалога не заканчивается ходом роли `model` — иначе API вернёт 400.

Модель возвращает строгий JSON: категории, уровень важности, масштаб, город, район,
улицы с домами и краткую суть.

Если `GEMINI_API_KEY` не задан или Gemini недоступен, включается **эвристический разбор**
по ключевым словам с извлечением улиц и домов — бот продолжает оповещать, помечая такие
сообщения как «без ИИ».

ИИ-ассистент в чате доступен с роли «Модератор»: обычное сообщение или `/ai вопрос`,
`/aireset` очищает контекст.

## Команды

`/start`, `/menu` — меню - `/id` — ваш ID и роль - `/cancel` — сбросить ввод -
`/help` — справка - `/vpn` — о проекте HydraSite - `/ai`, `/aireset` — ассистент (модератор+) - `/quota` — расход квоты (модератор+) -
`/stats`, `/models` — статистика и модели (админ+) - `/features` — возможности - `/logs`, `/logtail`, `/logclear` — журналы (суперадмин) -
`/check <ссылка>` — проверка ссылки на признаки мошенничества (флаг «Проверка ссылок»)

## Проверка ссылок

Команда `/check` и кнопка «🔍 Проверить ссылку» в главном меню (флаг
`linkcheck`, по умолчанию выключен). Разбирает адрес на признаки фишинга:
подмена букв под бренд, чужой бренд в домене, учётные данные перед `@`,
исполняемые схемы и файлы, слова-приманки, сокращатели. Сетевые
проверки — цепочка редиректов, возраст домена (RDAP), срок сертификата,
базы Google Safe Browsing (ключ — в разделе ключей, группа «Защита»;
без него сетевая часть работает частично; отключаются переменной
`LINKCHECK_NET=0`).

Бесплатно **200 проверок в сутки** всем, подписчикам — без дневного
предела. Частота — `LINKCHECK_RATE_LIMIT` проверок в минуту (по умолчанию
5, подписчиков не касается).

Вывод перечисляет признаки с весами и **никогда не говорит «ссылка
безопасна»** — отсутствие признаков не гарантия. Проверяйте источники
через официальные каналы.

## Язык интерфейса

Бот спрашивает язык при первом обращении — и у новых людей, и у тех, кто
пользовался ботом до появления выбора. Сменить можно позже из меню
(«🌍 Язык»).

Словарь — `radar/i18n.py`; непереведённая строка возвращает русский
вариант, а не служебный ключ.

С 4.7.6 **на английский переведено всё, что доступно обычному
пользователю:** главное меню, оповещения, погода текстом и картинкой
(включая розу ветров и фазы луны), новостные подборки, SOS, журнал,
загрузка видео, экран «Оповещения» целиком, «Предложить источник»,
`/help` и названия ролей.

На русском намеренно остаются экраны суперадминистратора — ключи,
управление ИИ, сеть, копии, журналы, редактор партнёрских проектов.
Их читает только владелец системы, и перевод удвоил бы поддержку
без единого читателя.

## Обновление с прежних версий

**С 4.6.1 поддержка формата базы 3.3.5 прекращена.** Импортёр `db.json`
удалён: код миграции с версии почти двухлетней давности никем не проверялся,
и держать его дальше означало возить с собой непроверенный путь через
все сборки.

### Полный путь обновления

Найдите свою версию в левом столбце и пройдите шаги сверху вниз.

| Откуда | Что делать |
|---|---|
| **2.x** (монолитный `bot.py`, `data/db.json`) | 1. Обновиться до **3.3.5** и дать боту один раз запуститься — он приведёт `db.json` к нужному виду.<br>2. Обновиться до **4.6.0** — база перенесётся из JSON в SQLite или PostgreSQL.<br>3. Обновиться до текущей версии. |
| **3.0 — 3.3.5** (`data/db.json`) | 1. Обновиться до **4.6.0** — на этой версии импортёр `db.json` работает в последний раз.<br>2. Убедиться, что рядом появился `db.json.migrated` и бот видит пользователей.<br>3. Обновиться до текущей версии. |
| **4.0 — 4.6.0** | Обновиться напрямую: `sudo bash install.sh`. |

Промежуточные версии берутся из релизов на GitHub. Пропускать шаг 4.6.0
при переходе с 3.x нельзя — без него данные останутся в JSON, а новый код
их не прочитает и молча начнёт с пустой базы.

### Что можно делать в панели

Панель повторяет права бота, а не расширяет их: роль означает в обоих
местах одно и то же.

- **Модератор** правит список источников — добавляет и удаляет
  Telegram-каналы, RSS-ленты и сообщества ВКонтакте. Разбор ссылок общий
  с ботом (`radar/sourceedit.py`), поэтому `@name`, `t.me/name` и голое
  имя дают один результат в обоих местах. Очередь предложений остаётся
  в боте: там вместе с решением уходит ответ приславшему.
- **Модератор** правит часовой пояс и время погоды у пользователя —
  когда это делает не сам человек, а администрация по его просьбе.
- **Суперадминистратор** включает и выключает возможности.
- **Суперадминистратор** заводит и правит партнёрские проекты — название,
  ссылку, описание, значок, порядок, видимость и промокоды: всё то же, что
  в боте. Заводить проект с описанием в переписке неудобно, а в панели
  поле описания видно целиком.
- **Суперадминистратор** задаёт ключи ИИ и токены сервисов, а во вкладке
  «Файлы» видит раздачу целиком: кому выдана ссылка, есть ли у человека
  подписка, забрали файл или он ещё ждёт, сколько осталось до сгорания.
  Ссылку можно отключить досрочно.

Панель работает в светлой и тёмной темах — переключатель в шапке, выбор
запоминается в браузере, по умолчанию берётся системный.

**Ключи вводятся, но не показываются.** Существующее значение видно только
маской вида `AIza…9kQw`: проверить, тот ли ключ вставлен, по ней можно,
а увести — нет. Доступ к перехваченной сессии панели не должен означать
доступ ко всем ключам сразу. Полное значение остаётся в `.env` на сервере.
В журнал панели пишется имя изменённого ключа и никогда значение — журнал
читается в самой панели.

Формы защищены скрытым токеном, привязанным к сессии, вдобавок к
`SameSite=Lax` у cookie: одна мера задаётся одной строкой кода, и её
правка молча сняла бы защиту.

### Веб-панель по домену

После получения сертификата остаётся шаг, который делается **в Telegram,
а не на сервере**: привязать домен к боту.

1. Откройте **@BotFather**
2. Команда `/setdomain`
3. Выберите своего бота
4. Пришлите адрес панели: `https://ваш-домен`

Без этого виджет входа показывает только «Bot domain invalid», и по этой
надписи догадаться, что делать, невозможно. Адрес должен совпадать точно —
со схемой `https://` и без пути в конце.

**По IP-адресу вход через Telegram не работает вовсе:** виджет принимает
только домены. Это ограничение Telegram, а не настройка панели.

### Переезд на другой сервер

На **старой** машине — одна команда, без полной установки:

```bash
curl -fsSLo radar-install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
sudo bash radar-install.sh --migrate
```

Установщик соберёт копию (база, `.env`, файлы данных) и спросит, как
передать её на новую машину. **Два варианта:**

**1. Вручную — надёжный путь.** Файл копии переносится любым способом
(scp, флешка), установщик на новой машине разворачивает его сам:

```bash
# на старой машине:
scp /root/radar_bot/backups/radar-backup-ГГГГММДД-ЧЧММСС.tar.gz пользователь@новый-сервер:~/

# на новой машине (нужен Docker: curl -fsSL https://get.docker.com | sh):
curl -fsSLo radar-install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
sudo bash radar-install.sh --restore
```

`--restore` без имени возьмёт архив из текущего каталога: положите файл
рядом с установщиком и запустите.

**2. Одноразовой ссылкой — ⚠️ путь ещё не проверен на живом переезде.**
Установщик склеит копию с самим собой в один самодостаточный файл,
поднимет одноразовую раздачу и напечатает две команды для новой машины:

```bash
curl -fsSLo radar-restore.sh http://АДРЕС-СТАРОГО-СЕРВЕРА:8899/ТОКЕН
sudo bash radar-restore.sh
```

Скачанный файл содержит и код бота, и данные — GitHub новому серверу не
нужен. Пока ссылка жива, установщик ждёт скачивания с обратным отсчётом;
Ctrl+C отменяет, закрытие терминала не прерывает. Ссылка срабатывает один
раз и живёт 30 минут, а внутри — токен бота и пароли, так что ссылку
никому не пересылайте; **порт 8899 должен быть проброшен на роутере
старого сервера на саму машину** — без проброса новый сервер не
подключится, и тогда проще вернуться к ручному варианту.

В обоих случаях дальше идёт обычная установка поверх данных копии:
дамп заливается **до** старта бота, а после запуска система пересчитывает
пользователей, локаций и источники и сообщает, сошлось ли.

**Старый бот не выключается автоматически.** Два экземпляра с одним токеном
отбирают друг у друга обновления, поэтому пока идёт проверка, новый бот
может отвечать через раз — это нормально. Убедитесь, что новый работает,
и только потом остановите старый:

```bash
cd /root/radar_bot && docker compose down
```

Если в копии дамп PostgreSQL, а на новой машине выбрана SQLite, залить его
нельзя — это разные диалекты SQL. Установщик скажет об этом прямо: выберите
PostgreSQL либо переносите файл `data/radar.db` руками.

### Полное удаление

Флаг `--uninstall` установщика останавливает и удаляет контейнеры и образ,
**сохраняя** базу и настройки. Чтобы убрать систему целиком — база, `.env`,
копии, журналы, каталог установки:

```bash
curl -fsSLo uninstall.sh https://raw.githubusercontent.com/Chistovik92/radar/main/tools/uninstall.sh
bash uninstall.sh
```

Скрипт самодостаточен: работает и на сломанной установке, сеть
и репозиторий не нужны. Спрашивает явное «да» и перед удалением умеет
снять последнюю копию (без кэша видео и журналов). Для автоматизации —
флаг `--yes`; нестандартный каталог — `RADAR_HOME=/путь`.

### Выбор устанавливаемой версии

По умолчанию ставится код из `main` — самый свежий, независимо от того,
оформлен он релизом или нет.

```bash
sudo bash install.sh --versions          # что вообще доступно
sudo bash install.sh --version=v4.6.1    # поставить конкретный релиз
```

Установка более старого релиза **и есть откат**. Он не запрещён и не
требует подтверждения: если новая версия сломалась, вернуться нужно
немедленно, а не доказывать установщику, что вы понимаете последствия.
Снимок перед перезаписью снимается в любом случае.

Если установка сорвётся, среди предложенных действий появится пункт
«поставить предыдущий релиз с GitHub» — на случай, когда сломан сам код
и снимок не помогает.

### Перед любым обновлением

```bash
sudo bash install.sh --backup
```

Копия кладётся рядом с установкой. Если обновление сорвётся, установщик
сам предложит восстановиться; вручную это делается так:

```bash
sudo bash install.sh --rollback
```

Схема базы проверяется на совместимость при каждом старте: если она осталась
от версии с ошибкой, таблицы пересоздаются с сохранением пользователей,
локаций и источников.

## Ограничения

- Читаются только **публичные** веб-превью каналов (`t.me/s/<канал>`); закрытые недоступны.
- Nominatim ограничивает геокодирование одним запросом в секунду — при массовом добавлении
  локаций стоит поднять свой инстанс.
- JSON-хранилища хватает на сотни пользователей; дальше нужен SQLite или Postgres.
- Классификация вероятностная: возможны ложные срабатывания и пропуски.
  **Система не заменяет официальные каналы оповещения.**

## Загрузка видео по ссылке

Функция под флагом `media_download` (по умолчанию выключена): пришлите ссылку —
бот покажет доступные качества с размерами и отправит файл. Поддерживаются
YouTube, VK Видео, RuTube, Одноклассники, Дзен, TikTok, X, Instagram и другие
площадки, которые умеет yt-dlp.

Предел отправки у обычного Bot API — 50 МБ. Чтобы поднять его до 2 ГБ,
запустите собственный Bot API Server:

```bash
# в .env: TELEGRAM_API_ID, TELEGRAM_API_HASH с my.telegram.org
#         TELEGRAM_API_SERVER=http://telegram-bot-api:8081
docker compose --profile media up -d
```

Скачивайте только то, на что у вас есть право: правила площадок и авторские
права функция не отменяет.

## Крупные файлы по ссылке

Telegram принимает от ботов не больше 50 МБ. Раньше на этом разговор
заканчивался: «выберите качество ниже — или поднимите собственный Bot API
Server». Оба совета верны и оба неуместны, когда качества ниже нет,
а второй сервер ради одного файла никто поднимать не станет.

Если задан `SHORT_BASE_URL` — внешний адрес, на котором открыта панель, —
файл отдаётся ссылкой: он не отправляется в мессенджер вовсе, человек
скачивает его сам. Предел Telegram при этом не обходится, а объезжается.

Ссылку получает только пользователь бота: её выдаёт бот в переписке.
Сама ссылка — секрет, и кто её получил, тот скачает: проверить учётную
запись Telegram при обычном запросе из браузера невозможно. Поэтому имя
файла непредсказуемо (32 знака), ссылка живёт сутки, а раздача целиком
ограничена бюджетом места — забитый диск остановил бы оповещения.

Просроченное и лишнее сверх бюджета убирается раз в цикл, вместе
с остатками прерванных загрузок.

## Кнопка SOS

Отдельная кнопка в главном меню: бот запрашивает геопозицию и отправляет её
доверенному контакту вместе с просьбой о помощи — координаты, разобранный
адрес, время и ссылка на карту, плюс отдельным сообщением сама геоточка.
Сигнал повторяется каждые 10 минут, пока отправитель не нажмёт «Я в порядке».

Важное ограничение платформы: Telegram не даёт боту написать первым тому,
кто с ним не общался. Поэтому доверенный контакт получает ссылку-приглашение
и должен один раз нажать «Старт». Пока он этого не сделал, сигнал уходит
администраторам системы.

Включается флагом `sos` в `/features`. **Бот не заменяет экстренные службы** —
при угрозе жизни звоните 112.

## Подписка

Подписка одна на бота. Она открывает две вещи сразу:

- новостные подборки по всем тематикам;
- загрузку видео без дневного предела.

**Раздельно эти части не продаются.** Модель под ними и раньше была одна —
оплата любой открывала обе, — но человек видел два предложения и разумно
заключал, что покупать надо оба. Продавать дважды одно и то же ощущение
нельзя, поэтому вход теперь один: `/subscription` или кнопка из раздела
видео.

**Пробный период — 7 дней**, один раз на человека. Он предлагается сразу,
а не после отказа от покупки: иначе увидят его только те, кто дошёл
до отказа.

**Оповещения об опасности бесплатны всегда** и от подписки не зависят.
Это правило проекта, а не текущая настройка.

Правка тарифов — в управлении, кнопка «💳 Подписка».

## Новостные подборки

Планируются к версии 4.3: утренняя и вечерняя сводка по выбранным тематикам
в одном сообщении, предложение источников пользователями, подписка через
Telegram Stars. Устройство и каталог тематик — в
[docs/NEWS_DIGEST.md](docs/NEWS_DIGEST.md).

Оповещения об опасности, ЖКХ, погода и локации остаются бесплатными навсегда.
