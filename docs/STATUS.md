# Состояние проекта

Документ для восстановления контекста: с чего продолжать, если работа
возобновляется в новом чате, на другой машине или другим человеком.
План развития — в [ROADMAP.md](ROADMAP.md), заработок — в
[MONETIZATION.md](MONETIZATION.md).

**Версия:** 4.9.4 · **Автор:** SecretHero · **Обновлён:** сентябрь 2026
**Репозиторий:** https://github.com/Chistovik92/radar

---

## Что это

Telegram-бот мониторинга городских угроз и аварий ЖКХ по адресам пользователя.
Публичные каналы служб ЖКХ, МЧС, администраций города, района и области плюс
RSS-ленты СМИ разбираются ИИ Google Gemini, события сопоставляются
с сохранёнными локациями.

**Продакшен:** контейнеры `radar_container` и `radar_db` на ARM-коробке
RK3318, бот `@SecretHeroBot`, город Саратов.

**Установка и обновление одной командой:**

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh)
```

## Ключевые решения и почему они такие

**Подборки отделены от оповещений.** Оповещение означает «происходит сейчас»
и приходит немедленно; подборка — спокойное чтение в выбранное время. Если
смешать, люди перестанут реагировать на оба. Это же причина, по которой
подписка платная только для подборок: всё, что касается безопасности,
бесплатно навсегда.

**Тихие часы не глушат срочное.** Военные угрозы и МЧС проходят всегда —
в этом смысл системы. Придерживается только ЖКХ и погода.

**Антиспам сравнивает основы слов, а не точный текст.** Городские каналы
пересказывают одно событие разными формулировками и падежами; точное
сравнение их не ловит.

**Вход в панель — только Telegram Login.** Паролей нет намеренно: учётная
запись уже подтверждена, роль лежит в базе бота, а лишний секрет пришлось бы
где-то хранить. Проверяются подпись, свежесть и роль — все три обязательны.

**Вид сводки погоды выбирает пользователь, а не администрация.** Картинка
нагляднее, но не прогрузится при ограничениях мобильного интернета — а это
ровно тот случай, ради которого система существует. Поэтому переключатель
в личных настройках, а текст остаётся значением по умолчанию.

**Всё управление ИИ — за одним входом.** Раньше сравнение провайдеров
открывалось и из «Управления», и из раздела ключей; теперь есть раздел
«Управление ИИ»: провайдер разбора, сравнение, модели с квотой, ключи.

**Политика перезапуска — `unless-stopped`.** В 4.0.3 я поставил
`on-failure:5`, чтобы цикл рестартов не маскировал ошибку. Оказалось хуже:
после штатной остановки и после перезагрузки сервера контейнер не поднимался,
и бот оставался выключенным молча. Для системы оповещения это опаснее цикла
рестартов — тем более что от него защищает диагностика: при неверной
конфигурации установщик просто не запускает бота.

**Установщик пересоздаёт контейнер (`--force-recreate`).** Публикация портов,
политика перезапуска и лимиты памяти применяются только при создании
контейнера: без пересоздания обновлённый compose остаётся без эффекта.

**Панель слушает только localhost по умолчанию.** Порт публикуется
как `127.0.0.1:8080`, доступ — через SSH-туннель. Открыть наружу можно,
но тогда обязательны `WEB_BIND=0.0.0.0`, `WEB_HTTPS=1` и reverse proxy
с сертификатом: без него cookie сессии уходит открытым текстом.

**Разделы панели повторяют права бота, а не расширяют их.** Модератор видит
источники и пользователей, администратор — ещё события, суперадминистратор —
возможности, копии и журнал. Роль проверяется на каждом запросе, а не только
при входе.

**Звёзды Telegram зачисляются на баланс самого бота.** Отдельный счёт или
эквайринг не нужны; баланс виден в @BotFather → Payments, вывод через
Fragment не раньше чем через 21 день — это правило Telegram.

**Терминала в панели нет.** Удалённое выполнение команд из браузера при
утечке сессии отдаёт весь сервер, а не данные бота.

**Добавление ключа VPN ничего не включает.** Из подписки приходят десятки
серверов разных протоколов и стран. Выбирать за администратора, через какой
пойдёт трафик бота, неправильно: от этого зависит и скорость, и то, из какой
страны бот виден площадкам. Пока сервер не выбран явно, выход остаётся прямым.

**Баланс провайдера проверяется до переключения.** У DeepSeek оплата по факту,
и ключ с нулевым остатком не отличается от рабочего до первого запроса —
а первым окажется разбор настоящей тревоги. Поэтому переключение делает
отдельный запрос баланса и отменяется при отказе.

**Ошибки VK приходят с кодом 200.** Коды 6 и 9 означают ограничение частоты,
а не мёртвый источник; пустой массив без ошибки не равен «новостей нет».
Всё это разобрано отдельно, иначе сообщества исключались бы из-за временных
ограничений.

**Без подтверждённой географии тревога не отправляется.** Прежде проверка
пропускалась, если ИИ не извлёк город, и сообщение федерального канала
о другом регионе уходило всем подписчикам. Теперь нужно совпадение города
или региона, либо упоминание в тексте; для адресных событий достаточно
совпадения улицы. Локации без географии получают только адресные оповещения.

**Событие в прошлом — не тревога.** «Вчера», «по итогам суток», «был сбит»,
«напомним» распознаются и уходят в утреннюю и вечернюю сводку. Смешивать
пересказ вчерашнего с сигналом «происходит сейчас» нельзя: люди перестают
реагировать на оба.

**Контакт SOS выбирается кнопкой Telegram.** С Bot API 7.0 пересланное
сообщение больше не раскрывает отправителя — `forward_from` не заполняется.
Штатный `request_users` работает и при закрытых настройках приватности.

**Военные угрозы — на весь город, ЖКХ — адресно.** БПЛА и ракетная опасность
касаются всех: одно сообщение на город со списком совпавших локаций. Аварии
ЖКХ ищутся по улице и дому, отдельным сообщением.

**Локации ближе 1 км склеиваются** транзитивно (union-find по haversine).
Радиус — `CLUSTER_RADIUS_M`.

**«Белые списки» не ищутся в новостях.** Операторы вводят их молча.
Предупреждение выдаётся автоматически вместе с оповещением о БПЛА, а при
отбое — с примечанием, что связь восстановят не сразу.

**Имя модели Gemini не зашито.** Google закрыл `gemini-2.5-flash` для новых
ключей до объявленной даты. Теперь при старте список кандидатов сверяется
с `models.list`, при 404 модель понижается на лету. Команда `/models`.

**Эвристика как последний рубеж.** Без Gemini или при исчерпанной квоте
разбор идёт по ключевым словам; такие события помечаются «(без ИИ)».

**Реклама не показывается в тревожных оповещениях.** `PROMO_IN_ALERTS=0`
по умолчанию: заработок на тревоге бьёт по доверию.

**Поддержка 2.x прекращена.** С 4.0 читается только формат 3.x. Застрявшим
на 2.x: обновиться до 3.3.5, дать боту раз запуститься, затем на 4.x.

## Переменные в docker-compose

Compose подставляет переменные **во всём файле сразу**, не разбирая профили.
Поэтому конструкция `${VAR:?...}` в сервисе под профилем роняет и обычную
сборку. Все переменные объявлены с пустым значением по умолчанию, а наличие
ключей проверяет установщик при включении профиля. За этим следит
`tools/lint_docker.py`.

## Загрузка видео

Отдельная функция под флагом `media_download`, по умолчанию выключена.
Ссылка перехватывается до свободного диалога с моделью, бот показывает
доступные качества с размерами и присылает файл.

Ограничения, которые нельзя обойти кодом:

- Telegram отдаёт от ботов файлы **не больше 50 МБ**. Снять предел до 2 ГБ
  можно только собственным Bot API Server: `docker compose --profile media up -d`,
  ключи `api_id` и `api_hash` берутся на my.telegram.org.
- Склейка выше 720p требует **ffmpeg** — он добавлен в образ и увеличивает
  его примерно на 150 МБ.
- Скачивание и склейка нагружают одноплатник сильнее всего остального бота
  вместе взятого. `MEDIA_CONCURRENCY=1` не стоит поднимать.

## Известные блокеры

**Gemini гео-блокируется с 28.08.2026.** Список моделей перестал
отдаваться со старого сервера: `400 FAILED_PRECONDITION, User location
is not supported for the API use`. 25 августа тот же ключ видел
37 моделей — блок появился между этими датами, без изменений в коде.
Бот продолжает работать на моделях по умолчанию, но автоподбор
недоступен; если генерация тоже блокируется, разбор уходит
на эвристику. Лечение — выход через свой узел (`EGRESS_PROXY`,
раздел 4.3) либо сервер в незаблокированном регионе.

**MAX (версия 4.2).** Два, не решаемых кодом:

1. Публиковать ботов могут только юрлица, ИП и самозанятые РФ. Без статуса
   бот останется тестовым.
2. Для боевой работы нужен webhook, то есть белый IP и HTTPS. У домашней
   коробки их обычно нет — варианты: Cloudflare Tunnel, VPS с reverse proxy
   или временно long polling.

Плюс ограничение платформы: **читать чужие публичные каналы в MAX нельзя** —
API бот-центричный. MAX это канал доставки, а не источник. Источники берём
из VK в 4.1.

**Новые столбцы дописываются через `ALTER TABLE`.** `create_all` создаёт только
недостающие таблицы: добавление поля в модель оставляло существующую базу
без него, и запросы падали с «no such column». Теперь при старте недостающие
столбцы дописываются, а существующие строки заполняются значением по умолчанию.
Пересоздание схемы остаётся крайней мерой — только при несовместимости типов.

**Схема проверяется на совместимость при каждом старте.** `create_all` только
досоздаёт недостающие таблицы и никогда не меняет существующие: база, созданная
версией с ошибкой в типе ключа, так и оставалась нерабочей — таблицы на месте,
вставка падает. Теперь тип ключа проверяется через `PRAGMA table_info`, и при
несовпадении схема пересоздаётся с переносом пользователей, локаций,
источников, флагов и служебных значений. История событий при этом очищается —
она восстановима из источников.

**Первичный ключ объявлен как `BigInteger().with_variant(Integer, "sqlite")`.**
SQLite подставляет автоинкремент только для `INTEGER PRIMARY KEY`; `BIGINT`
для него обычный тип, и вставка падала с «NOT NULL constraint failed: users.id».
В PostgreSQL нужен именно BigInteger — телеграмные идентификаторы не помещаются
в 32 бита.

**Перед обновлением снимается снимок установки** в `backups/rollback-<версия>-<дата>.tar.gz`:
файлы проекта и `.env`, без базы. Если новая версия не поднимается, установщик
предлагает откатиться; вручную — `bash install.sh --rollback`. Хранятся
последние 5 снимков.

**ERR-trap срабатывает даже при `set +e`.** Это не отключаемое поведение bash:
код возврата нужно снимать конструкцией `команда || код=$?`, иначе установка
обрывается там, где ожидалась проверка результата.

**Установщик обёрнут в функцию.** При `bash <(curl ...)` скрипт читается
потоком, и обрыв связи приводил к выполнению половины файла — однажды так
записалась половина проекта. Теперь тело в функции, вызов единственной строкой
в конце: при обрыве bash падает на разборе и не выполняет ничего. Надёжнее
всё же скачивать файл заранее.

**Журналы лежат в `data/logs/`** — единственном каталоге, видимом
одновременно боту и хосту. Журнал установки создаётся на каждый запуск
с датой в имени, журнал бота ротируется. Суперадминистратор забирает их
прямо из бота: `/logs`, `/logtail`, `/logclear`. Журналы контейнеров Docker
собираются отдельно скриптом `collect-logs.sh` — давать боту доступ к сокету
Docker означало бы отдать ему весь сервер.

**База по умолчанию — SQLite.** PostgreSQL на одноплатнике за роутером дал
три отказа подряд: пароль, искажённый Compose; зависание Alembic; ошибка
ленивой подгрузки. SQLite — файл рядом с ботом, без контейнера, пароля
и ожидания готовности. Код общий: обе базы работают через SQLAlchemy,
переключение — переменной `DB_BACKEND`.

**Схема базы создаётся напрямую из моделей, не через Alembic.** Синхронный
`command.upgrade` из рабочего потока порождал вложенный `asyncio.run()` поверх
уже работающего цикла событий и вешал запуск на ARM намертво — контейнер
перезапускался по кругу без единой строки ошибки. Alembic остался для будущих
изменений схемы и запускается отдельной командой.

**Первый запуск на слабом железе занимает минуты.** Миграции Alembic, перенос
данных и дозаполнение адресов на RK3318 идут до 5–10 минут. Установщик
показывает этапы и ждёт; появление строки «Run polling» означает готовность.

**Пароль PostgreSQL меняется только при создании базы.** Если правили
`DB_PASSWORD` на уже работающей установке, база продолжит ждать прежний пароль.
Установщик это обнаруживает и предлагает пересоздать том; прежний сохраняется
как `data/postgres.bak-<дата>`.

**Квота Gemini.** Бесплатный тариф жёстко ограничен; при исчерпании ассистент
недоступен до полуночи по тихоокеанскому времени (около 10–11 утра по Москве).
Расход — командой `/quota`.

**Память на RK3318.** PostgreSQL плюс бот — уже плотно. Настройки Postgres
занижены в `docker-compose.yml`. Веб-панель (4.3) вынесена отдельным
процессом с флагом, чтобы её можно было выключить.

## Разработка идёт на Python 3.12, образ собран на 3.11

Часть синтаксиса, разрешённого в 3.12, старая версия не принимает. Ни
`py_compile`, ни `ast.parse(feature_version=...)` этого не ловят: у f-строк
отдельный токенизатор. Поэтому есть `tools/lint_pyversion.py` — он берёт
версию из `Dockerfile` и разбирает f-строки вручную. Проверка встроена
в `stubcheck` и в CI.

## Как проверять изменения

```bash
python3 -m unittest discover -s tests   # 184 теста, без сети
python3 tools/stubcheck.py              # импорт 31 модуля с заглушками
python3 tools/lint_names.py             # сверка имён между модулями
python3 tools/lint_undefined.py         # обращения к неопределённым именам
python3 tools/lint_docker.py            # Dockerfile против .dockerignore
python3 tools/lint_pyversion.py         # совместимость с Python из образа
# на сервере, внутри контейнера:
docker compose run --rm radar python -m radar.doctor   # на сервере
bash ~/radar_bot/collect-logs.sh                       # все журналы в архив
python3 tools/stamp_headers.py --check  # подпись автора на месте
python3 tools/build_installer.py        # пересборка install.sh
bash -n install.sh
```

`install.sh` генерируется из исходников и вручную не правится. CI проверяет
соответствие манифесту и роняет сборку при расхождении.

## Эксплуатация

```bash
docker logs -f radar_container                    # логи бота
docker logs -f radar_db                           # логи базы
cd ~/radar_bot && docker compose restart          # перезапуск
docker exec radar_db pg_dump -U radar radar | gzip > radar-$(date +%F).sql.gz

bash install.sh --backup     # копия базы, .env и данных одной командой
bash install.sh --reset      # полный сброс: копия, затем установка с нуля
```

Перед обновлением сервера снимите копию `data/db.json` (для перехода 3.x → 4.0)
или дамп базы. Обязательно задайте `DB_PASSWORD` в `.env` — без него бот
не стартует.

## Ограничения системы

- Читаются только публичные веб-превью каналов (`t.me/s/<канал>`).
- Nominatim ограничивает геокодирование одним запросом в секунду.
- Классификация вероятностная: возможны ложные срабатывания и пропуски.
- Формулировка «не заменяет официальные каналы оповещения» должна
  оставаться везде.
- База растёт примерно на 50–150 МБ в месяц при мониторинге одного города;
  ограничивается `EVENT_RETENTION_DAYS`.
