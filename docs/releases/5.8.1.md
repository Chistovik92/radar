# v5.8.1 — проверенный переход с 4.9.x на 5.8

## Что проверено

Код каждого из **43 выпусков 4.9** (v4.9 … v4.9.9.4) создавал и наполнял
базу, после чего код 5.8 поднимал её тем же путём, что при запуске бота,
и пересохранял. На **SQLite** и на **PostgreSQL 16** — все 43 без потерь:

- недостающие таблицы и столбцы дописываются, схема не пересоздаётся —
  история событий не стирается;
- пользователи, роли, адреса, тихие часы, источники, флаги, служебные
  данные, история доставок, короткие ссылки и промокоды на месте;
- запись в формате 5.x (ключи других сетей, данные VPN и привязок)
  проходит поверх старых данных.

Переменные окружения между 4.9 и 5.8 только добавлялись, у всех есть
значения по умолчанию. Проверка оформлена как `tools/upgrade_check.py`
(`--postgres` — на PostgreSQL) и ловит намеренную поломку сохранения.

## Найдена и закрыта ловушка установщика

Сохранённый на сервере старый `install.sh` по пункту «Поставить последний
код (main)» ставил **свою же** версию: код лежит внутри файла. Кнопка
«Обновить» в панели 4.9.6–4.9.8.8 запускала именно его.

- С 5.8.1 установщик в этом месте сверяется с последним выпуском на GitHub
  и предлагает скачать и запустить его установщик.
- Для уже стоящих 4.9.x (их установщик не изменить):

```bash
cd ~/radar_bot
curl -fsSLo install.sh https://raw.githubusercontent.com/Chistovik92/radar/main/install.sh
sudo bash install.sh
# или прежним файлом с явной версией:
sudo bash install.sh --version=v5.8.1
```

С 4.9.8.9 и новее кнопка «Обновить» в панели ведёт на последний выпуск сама.

только на сервере.

Оповещения об угрозах — бесплатно; бот не заменяет официальные каналы
оповещения.
