# v5.9 — переход между SQLite и PostgreSQL с данными

До 5.9 смена базы в установщике давала **пустую** новую базу: старая
оставалась на диске, а пользователи, адреса, источники и история — в ней.
Теперь данные переезжают в обе стороны.

## Как это выглядит

При смене базы установщик спрашивает «Перенести данные из прежней базы
в новую?» и, если да:

1. собирает образ и поднимает PostgreSQL — и когда переходят на него,
   и когда уходят с него;
2. останавливает бота, чтобы источник не менялся посреди копии;
3. копирует все таблицы и сверяет число строк;
4. только после этого запускает бота на новой базе.

Прежняя база остаётся нетронутой: файл SQLite — рядом, как
`radar.db.bak-<дата>`, том PostgreSQL — на месте, так что вернуться
можно тем же меню. Если перенос не удался, всё возвращается как было.

Руками, внутри контейнера:

```bash
docker compose --profile postgres run --rm radar \
    python -m radar.cli db copy --from sqlite --to postgres
# обратно: --from postgres --to sqlite
# непустая цель заменяется только с --replace --yes
```

## Что сохраняется

Ключи и связи между таблицами; JSON, даты и логические значения
переводятся между диалектами; счётчики PostgreSQL выравниваются, так что
новые записи не спотыкаются о занятые номера. База от прежней версии без
новых столбцов переносится: недостающее получает значения по умолчанию.

## Как проверено

`tools/db_transfer_check.py` на настоящих SQLite и PostgreSQL 16: база
наполняется текущим кодом, переносится туда, сверяется строка в строку,
в неё добавляются новые записи, переносится обратно и снова сверяется;
перенос в непустую базу отвергается; бот поднимает результат. Это шаг CI
с сервисом PostgreSQL. Отдельно перенесена база, созданная кодом v4.9
на PostgreSQL, — в SQLite, с проверкой полной загрузки ботом.

⚠️ Сам сценарий установщика (Docker, `compose run`, остановка бота)
на сервере не проверялся — только его составные части.

Оповещения об угрозах — бесплатно; бот не заменяет официальные каналы
оповещения.
