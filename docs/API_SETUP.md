# Настройка внешних сервисов

Пошаговые инструкции для всего, что бот использует снаружи: ключи ИИ,
источники, загрузка видео, погода и карты.

**Быстрый путь:** большинство ключей задаются прямо в боте — «🛠 Управление» →
«🔑 Ключи доступа» (только суперадминистратор). Значения пишутся в `.env`,
маскируются при показе, часть применяется сразу, часть — после перезапуска
контейнера. Ниже описано, где эти ключи взять.

## 1. Telegram: токен бота

**Нужен всегда.** Без него бот не запустится.

1. Откройте [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Задайте отображаемое имя и юзернейм (должен оканчиваться на `bot`).
3. Скопируйте токен вида `123456789:AAE...`.
4. Впишите в `.env`: `BOT_TOKEN=...`

**Свой Telegram ID** — у [@userinfobot](https://t.me/userinfobot), в `.env`
как `SUPERADMIN_ID`. Этот пользователь получает полные права.

Если токен утёк — `/revoke` у @BotFather, старый перестанет работать.

## 2. Google Gemini

Основной провайдер: разбор новостей и ИИ-ассистент. Без ключа бот работает
на эвристике по ключевым словам — оповещения продолжают приходить, но точность
ниже.

1. Откройте [aistudio.google.com/apikey](https://aistudio.google.com/apikey).
2. Войдите в аккаунт Google, нажмите **Create API key**.
3. Скопируйте ключ и вставьте в боте: «Ключи доступа» → «ИИ» → «Google Gemini».

**Ограничения бесплатного тарифа** — порядка 10 запросов в минуту и несколько
сотен в сутки. Бот их учитывает: `AI_RPM`, `AI_RPD`, плюс резерв `AI_RESERVE`
специально под ассистента, чтобы фоновый разбор не съедал квоту диалога.
Текущий расход — команда `/quota`.

**Выбор модели.** `/models` показывает всё, что доступно вашему ключу.
Закрепить конкретную:

```
/setmodel gemini-3.6-flash                  — для ассистента
/setmodel gemini-3.5-flash-lite analysis    — для разбора новостей
```

Действует сразу; чтобы сохранилось после перезапуска, задайте `GEMINI_MODEL`
и `GEMINI_MODEL_ANALYSIS` в «Ключах доступа».

Модели периодически отключают. Бот сам переходит на следующую доступную,
но список стоит поглядывать: Google закрыл `gemini-2.5-flash` для новых
ключей раньше объявленной даты.

## 3. Другие провайдеры ИИ

Нужны для сравнения и как запасной вариант. Проверка запускается в боте:
«🛠 Управление» → «🧪 Проверка ИИ».

| Провайдер | Где получить ключ | Особенности |
|---|---|---|
| **Groq** | [console.groq.com/keys](https://console.groq.com/keys) | быстрый, щедрый бесплатный тариф |
| **Cerebras** | [cloud.cerebras.ai](https://cloud.cerebras.ai) | около миллиона токенов в сутки |
| **Mistral** | [console.mistral.ai](https://console.mistral.ai) | Франция; всего 2 запроса в минуту |
| **OpenRouter** | [openrouter.ai/keys](https://openrouter.ai/keys) | один ключ на десятки моделей |
| **DeepSeek** | [platform.deepseek.com](https://platform.deepseek.com) | самая низкая цена; можно сделать основным |
| **Z.ai / GLM** | [z.ai](https://z.ai) | часть моделей бесплатна |
| **Kimi** | [platform.moonshot.ai](https://platform.moonshot.ai) | до 1000 запросов в сутки |
| **Qwen** | [modelstudio.console.alibabacloud.com](https://modelstudio.console.alibabacloud.com) | международный эндпоинт |

**Смена основного провайдера.** «🛠 Управление» → «🤖 Провайдер ИИ»: Gemini
или DeepSeek. Перед переключением бот запрашивает баланс — у DeepSeek оплата
по факту, и ключ с нулевым остатком иначе выяснился бы на первой же тревоге.
Смена действует со следующего разбора.

**На что смотреть в результатах.** Не на общую точность, а на колонку
**«военные темы»**: провайдер, который отказывается разбирать сообщения
о БПЛА, для оповещений непригоден, каким бы точным он ни был в остальном.
Проверка прогоняет два таких кейса специально.

Второй момент — **доступность из вашей сети**. Часть площадок блокирует
российские адреса; если провайдер отвечает «таймаут», дело обычно в этом,
и помогает прокси (раздел 9).

## 4. ВКонтакте: чтение сообществ

Позволяет читать стены открытых сообществ — полезно, потому что ведомства
дублируют туда публикации из Telegram.

1. Откройте [vk.com/apps?act=manage](https://vk.com/apps?act=manage) →
   **Создать приложение** → тип **Standalone**.
2. В настройках приложения найдите **Сервисный ключ доступа**.
3. Вставьте в боте: «Ключи доступа» → «Источники» → «ВКонтакте».

Сервисного ключа достаточно: он даёт чтение открытых данных без входа
пользователя.

**Подводные камни**, которые бот обрабатывает: VK отвечает кодом 200 с телом
ошибки вместо 429; код 6 — слишком часто, код 9 — флуд-контроль; пустой
массив без ошибки не означает «новостей нет».

## 5. Одноклассники

Сложнее остальных: публичных RSS у OK нет, а API требует регистрации
приложения и подписи каждого запроса.

1. Зарегистрируйтесь на [apiok.ru](https://apiok.ru) и создайте приложение.
2. Дождитесь подтверждения — оно не мгновенное.
3. Получите три значения: **application key** (публичный),
   **access token** и **secret key**.
4. Впишите их в боте: «Ключи доступа» → «Источники».

Без ключей источник просто отключается и не мешает остальным.

Разбор HTML-страниц вместо API мы не используем: он ненадёжен и противоречит
правилам площадки.

## 6. Свой Bot API Server: файлы до 2 ГБ

Нужен только для загрузки видео. Обычный Bot API отдаёт от ботов файлы
не больше **50 МБ** — обойти это кодом нельзя.

1. Откройте [my.telegram.org](https://my.telegram.org), войдите по номеру
   телефона.
2. **API development tools** → создайте приложение (название любое).
3. Скопируйте **api_id** (число) и **api_hash** (строка).
4. Впишите в боте: «Ключи доступа» → «Медиа», а также
   `TELEGRAM_API_SERVER=http://telegram-bot-api:8081`.
5. В `.env` поставьте `MEDIA_ENABLED=1`.
6. Перезапустите с профилем:

```bash
cd ~/radar_bot
docker compose --profile media up -d
```

Установщик поднимет профиль сам, если увидит `MEDIA_ENABLED=1` и оба ключа.

**Важно:** `api_id` и `api_hash` привязаны к вашему аккаунту Telegram — это
не то же самое, что токен бота. Не публикуйте их.

Кэш сервера чистится сам: файлы старше 6 часов и при заполнении диска.

## 7. Мессенджер MAX

⚠️ **Адаптер реализован, но не проверен на живом сервере.** Включайте только
для испытаний: флаг `platform_max` в «Возможностях».

1. Зарегистрируйтесь в кабинете разработчика MAX (dev.max.ru или бизнес-кабинет).
2. **Пройдите верификацию владельца** — Госуслуги, Alfa ID, Т-Business ID или
   СберБизнес ID. Публиковать ботов могут только юрлица, ИП и самозанятые РФ.
3. Получите токен через `@MasterBot` командой `/create`.
4. Впишите `MAX_BOT_TOKEN` в `.env`.
5. Проверьте `MAX_API_URL`: в документации встречаются
   `platform-api.max.ru` и `platform-api2.max.ru`.

Модерация занимает до 48 часов в рабочие дни. Для боевой работы MAX требует
webhook — понадобится белый IP и HTTPS; long polling годится для проверки.

**Ограничение платформы:** читать чужие публичные каналы в MAX нельзя. API
бот-центричный: `chat_id` приходит только после того, как владелец добавит
вашего бота в свой канал. Поэтому MAX — канал доставки, а не источник новостей.

## 8. Погода и карты: без ключей

Ничего настраивать не нужно.

- **Open-Meteo** — погода и прогноз, работает без регистрации.
- **Nominatim (OpenStreetMap)** — определение адреса по координатам.

У Nominatim есть условие: **не чаще одного запроса в секунду**. Бот его
соблюдает. При большом числе пользователей имеет смысл поднять свой экземпляр.

## 9. Выход в сеть через свой узел

Пригодится, если провайдер ИИ или источник недоступен из вашей сети.
Настраивается целиком в боте, править `.env` вручную не нужно.

1. «🛠 Управление» → «🌐 Выход в сеть» → «Добавить ключ или подписку».
2. Пришлите одно из: ссылку на подписку, `vless://`, `ss://`, `trojan://`
   или `socks5://host:port`.
3. **Выберите сервер.** Это отдельный шаг: из подписки приходят десятки
   узлов, и пока конкретный не выбран, трафик идёт напрямую.
4. Нажмите «Включить выход».
5. Поднимите профиль на сервере:

```bash
cd ~/radar_bot
docker compose --profile proxy up -d
```

Бот сам пишет конфигурацию в `data/singbox/config.json`. Поддерживаются
VLESS (в том числе Reality), Shadowsocks, Trojan, SOCKS5 и HTTP.

Кнопка «Обновить подписку» перечитывает список. Если выбранный сервер из неё
исчез, выход выключается и бот об этом сообщает — молча переключаться
на другой узел он не будет.

Этот же выход используется для загрузки видео.

## 10. Оплата подписки на подборки

Отдельный платёжный сервис не нужен: Telegram Stars — встроенный механизм.

1. Ничего не подключайте — оплата работает сразу.
2. Тарифы задаются в боте: «📰 Новостные подборки» → «💰 Тарифы и оплата»
   (только суперадминистратор). Формат «дни:звёзды».
3. Звёзды зачисляются **на баланс самого бота**. Посмотреть:
   @BotFather → выбрать бота → Payments.
4. Вывод — через [Fragment](https://fragment.com), но не раньше чем через
   21 день после оплаты. Это правило Telegram, а не системы.
5. Возвраты выполняет поддержка Telegram по обращению пользователя;
   бот в этом не участвует.

Минимальная цена — одна звезда: счёт дешевле Telegram не примет.

## 11. Проверка настроек

**В боте:**

```
/models        какие модели Gemini доступны ключу
/quota         расход квоты Gemini
/bench         сравнение провайдеров ИИ
/checksources  доступность источников
/logs          журналы бота и установки
```

**На сервере:**

```bash
cd ~/radar_bot
docker compose run --rm radar python -m radar.doctor   # полная диагностика
docker logs -f radar_container                          # что происходит сейчас
bash collect-logs.sh                                    # все журналы в архив
```

Диагностика проверяет зависимости, конфигурацию, базу, полный цикл записи
и чтения, разбор старых данных и доступ к Telegram. Установщик запускает
её до старта бота: при ошибке бот не поднимается, а вы получаете отчёт.

## 12. Свой сервер RustDesk

Флаг `rustdesk` в «Возможностях» открывает раздел бота с адресом и ключом
своего сервера удалённого доступа, числом подключений и управлением
контейнерами. Сами контейнеры (`hbbs`+`hbbr`, образ
`rustdesk/rustdesk-server`) — отдельный профиль `docker-compose.yml`,
установщик умеет разворачивать его сам.

**При установке или обновлении** установщик спросит, поднимать ли
RustDesk, и попросит внешний адрес сервера (IP или домен) — именно
его получат клиенты RustDesk при подключении.

Если сертификат панели уже получен через `tls.sh`, адрес спрашивается
формально: домен берётся из первой строки `tls/Caddyfile` и предлагается
в квадратных скобках — `Enter` соглашается с ним. Это тот же домен,
на который выдан сертификат. Ввести другой адрес по-прежнему можно,
он перебивает подсказку.

Ответ `y` пишет в `.env`:

```
RUSTDESK_ENABLED=1
RUSTDESK_PUBLIC_HOST=ваш-адрес-или-домен
```

**Вручную**, если бот уже установлен и вопрос пропущен: впишите те же
две строки в `.env` и поднимите профиль:

```bash
cd ~/radar_bot
docker compose --profile rustdesk up -d
```

При каждом следующем запуске установщик проверяет, что под именами
`radar_hbbs`/`radar_hbbr` — действительно `rustdesk-server`, а не что-то
постороннее, занявшее эти имена: если образ не совпал, будет
предупреждение, а не тихая подмена.

**Порты наружу.** В отличие от остальных сервисов бота, RustDesk обязан
быть доступен из интернета — публикуются пять портов: `21115`, `21116`
(TCP и UDP), `21117`, `21118`, `21119`. Их нужно пробросить на роутере,
если сервер стоит за NAT.

**Ключ клиента.** Публичный ключ пары, которую RustDesk создаёт при
первом запуске, читается ботом напрямую — общий с `hbbs` том смонтирован
в контейнер бота только для чтения (`RUSTDESK_KEY_PATH`, по умолчанию
`data/rustdesk/id_ed25519.pub`). Docker-сокет для этого не используется —
он нужен только для числа подключений и управления контейнерами.

**Число подключений** — не официальная метрика RustDesk (открытая версия
её не публикует вовсе), а оценка по установленным TCP-соединениям
на служебном порту hbbs и порту релея hbbr, полученная через `docker exec`
внутрь контейнеров. Управление (запуск/остановка/перезапуск) идёт
тем же путём — через сокет Docker, как «Обновление из панели»: тот же
уровень риска (сокет внутри контейнера равносилен root на хосте),
поэтому у флага `rustdesk` цена ровно такая же.

**Тот же набор в веб-панели.** Раздел «RustDesk» в «Обзоре» (только
суперадминистратор) показывает адрес и ключ, число подключений и три
кнопки управления — то же самое, что в боте, но без деления на уровни
доступа: панель и так открыта только администрации.

## 13. VPN-панели (с 5.0, несколько — с 5.0.1)

Флаг `vpn` в «Возможностях» открывает раздел «🔐 VPN». Сами панели
ставятся отдельно — бот только обращается к их API. Панелей может быть
до шести сразу, разных видов: каждая — слот `VPN1_*` … `VPN6_*`,
в разделе ключей бота это группы «VPN 1» … «VPN 6». Выдаёт доступ
только суперадминистратор.

Общие настройки — группа «VPN»:

```
VPN_DAYS=30
VPN_TRAFFIC_GB=0
```

`VPN_DAYS` — срок выдачи и шаг продления, `VPN_TRAFFIC_GB=0` — без
предела. Комментарии в той же строке `.env` не пишите: они станут
частью значения.

Поля слота (на примере первого):

| Поле | Что это |
|---|---|
| `VPN1_KIND` | вид: `3xui`, `xui`, `sui`, `marzban`, `pasarguard`, `marzneshin`, `remnawave`, `hiddify`, `outline`, `wgeasy` |
| `VPN1_TITLE` | подпись для людей, например «Нидерланды» |
| `VPN1_URL` | адрес панели, с секретным путём, если он есть |
| `VPN1_TOKEN` | токен или ключ API |
| `VPN1_USER`, `VPN1_PASS` | логин и пароль — где панель это позволяет |
| `VPN1_INBOUND` | номер подключения — для 3x-ui и x-ui |
| `VPN1_SUB_URL` | адрес подписки — для 3x-ui, x-ui, s-ui; клиентский путь — для Hiddify |
| `VPN1_GROUPS` | через запятую: группы, сервисы, отряды, подключения или протоколы — смотря по панели |
| `VPN1_CERT` | SHA-256 сертификата — для панели на самоподписанном; для Outline обязателен |

Настройки из 5.0 (`VPN_PANEL`, `VPN_PANEL_URL` и прочие без номера)
читаются как первый слот, пока `VPN1_*` не заданы, — после обновления
ничего переносить не нужно. `VPN_AUTO_ROLE` убран: выдачи по роли больше нет.

**3x-ui** (`3xui`, ветки 2.x и 3.x определяются сами). Адрес — вместе
с секретным путём панели. Вход — токеном из «Настройки → Безопасность →
API» или логином с паролем. Нужен номер подключения (`INBOUND`);
в 2.x — с протоколом vless, vmess или trojan. Ссылку подписки собирает
бот из `SUB_URL` — адреса службы подписки, например
`https://example.ru:2096/sub`, — и `subId` клиента.

**x-ui** (`xui`, форк alireza0). То же, что 3x-ui 2.x, но токенов у панели
нет — только логин с паролем.

**s-ui** (`sui`). Адрес — вместе с путём панели, токен — из
«Настройки → API». В `GROUPS` — номера подключений (inbounds), к которым
привязывается клиент; в `SUB_URL` — адрес подписки s-ui.

**Marzban** (`marzban`). Токен или логин с паролем администратора.
В `GROUPS` — протоколы через запятую (`vless`, `vmess`, `trojan`,
`shadowsocks`), по умолчанию vless; подключения панель назначает сама.

**PasarGuard** (`pasarguard`). Ключ API из раздела ключей панели или логин
с паролем. В `GROUPS` — номера групп: без них запись заведётся, но без
доступа к узлам.

**Marzneshin** (`marzneshin`). Токен или логин с паролем. В `GROUPS` —
номера сервисов.

**Remnawave** (`remnawave`). Только токен из «API Tokens» — входа по паролю
у API нет. В `GROUPS` — uuid внутренних отрядов (squads). Если бот
обращается к бэкенду напрямую по HTTP внутри сети Docker, он сам
добавляет `X-Forwarded-Proto` и `X-Forwarded-For`.

**Hiddify** (`hiddify`). Адрес — с путём администратора:
`https://домен/<admin_proxy_path>`. Токен — uuid администратора.
`SUB_URL` — клиентский путь `https://домен/<client_proxy_path>`: человек
получает страницу, с которой ставятся все приложения. Срока как даты
у Hiddify нет — бот пересчитывает число дней от сегодняшнего.

**Outline** (`outline`). Адрес — `apiUrl` из Outline Manager целиком,
с секретным путём. `CERT` — `certSha256` оттуда же: сертификат у сервера
самоподписанный, и без закрепления адрес с секретом ушёл бы любому, кто
встал посередине. Сроков у Outline нет: доступ действует, пока его
не выключат; выключение — предел трафика в ноль.

**wg-easy** (`wgeasy`, 15.x). Логин и пароль администратора. Человек
получает одноразовую ссылку на файл WireGuard; нужна снова — бот выпустит
новую. Предела трафика у wg-easy нет.

**Панель на голом IP с самоподписанным сертификатом** (частый случай
у 3x-ui) — задайте `CERT`: SHA-256 сертификата, 64 шестнадцатеричных
знака, двоеточия допустимы. Проверка сертификата при этом не отключается,
а сводится к сравнению с отпечатком. Узнать его:

```bash
openssl s_client -connect IP:ПОРТ </dev/null 2>/dev/null \
  | openssl x509 -noout -fingerprint -sha256
```

**Проверка.** В разделе «🔐 VPN» у суперадминистратора есть кнопка
«🩺 Проверить панели» — все панели разом. Из командной строки:

```bash
python -m radar vpn check            # только чтение
python -m radar vpn selftest --yes   # полный круг на записи radar_selftest
```

`selftest` пишет в панели: заводит `radar_selftest`, проверяет по ответу
панели срок, выключение, включение и ссылку и оставляет запись
выключенной. ⚠️ Клиенты сверены с исходным кодом панелей и прогнаны через
их эмуляторы, но с живыми панелями не работали — начните с этих команд.

## 14. Продажа VPN и оплата (с 5.0.2)

Флаг `vpn_sales` в «Возможностях» добавляет в раздел «🔐 VPN» кнопку
«💳 Купить доступ». Нужны настроенные панели (раздел 13) и тарифы.
Все значения — в разделе ключей бота, группа «Продажа VPN».

```
VPN_PLANS=30:0:3:199; 90:0:3:499
VPN_CURRENCY=RUB
VPN_PLAN_SLOTS=1,2
PAY_PROVIDER=manual
```

Тариф — `дни:трафикГБ:устройства:цена`; трафик и устройства `0` —
без предела. Негодный кусок строки пропускается, остальные тарифы
продаются. `VPN_PLAN_SLOTS` пусто — продаётся доступ на всех
настроенных панелях.

**manual.** Бот денег не принимает. В `PAY_MANUAL_NOTE` напишите, куда
и как платить, — текст покажется под заказом. Суперадминистратор получит
письмо с кнопкой «✅ Оплата получена»; все заказы — в «🧾 Заказы».

**cryptopay.** В @CryptoBot: Crypto Pay → Create App → токен
в `PAY_CRYPTOPAY_TOKEN`. Для пробы без настоящих денег —
`PAY_CRYPTOPAY_TESTNET=1` и токен из @CryptoTestnetBot.
`PAY_CRYPTOPAY_ASSETS` — какие монеты принимать (например `USDT,TON`),
пусто — все доступные. Цена задаётся в валюте `VPN_CURRENCY`,
Crypto Pay пересчитывает её сам.

Об оплате бот узнаёт, спросив состояние счёта, когда человек нажимает
«Я оплатил»: у бота нет входящего адреса для webhook. Проверка подписи
webhook (`payments.verify_signature`) написана заранее, но не подключена.

⚠️ До включения продаж посмотрите в @CryptoBot текущие комиссию, лимиты
и условия вывода — в код и документацию они не вписаны, потому что
меняются. С настоящими платежами продажи не проверялись: начните
с тестовой сети.

## 15. Discord (с 5.5)

1. [discord.com/developers/applications](https://discord.com/developers/applications)
   → New Application → раздел **Bot** → Reset Token. Токен —
   в `DISCORD_BOT_TOKEN` (раздел ключей, группа «Discord»; применяется
   после перезапуска).
2. Привилегированные намерения (Message Content, Server Members,
   Presence) **не включайте**: боту они не нужны, он работает только
   слеш-командами.
3. **OAuth2 → URL Generator**: области `bot` и `applications.commands`,
   права — Send Messages. По полученной ссылке добавьте бота на сервер.
4. В Discord: Настройки → Расширенные → режим разработчика; ПКМ
   по каналу → Copy Channel ID → в `DISCORD_CHANNEL_ID`. Без него бот
   отвечает на команды, но в канал ничего не публикует.
5. `DISCORD_SUMMARY_TIME` — время суточной сводки по серверу,
   по умолчанию 20:00.
6. Включите возможность «Discord» (`platform_discord`) и перезапустите бота.

Слеш-команды регистрируются глобально; Discord может показывать их
не сразу — до часа после первого запуска. ⚠️ С живым Discord адаптер
не проверялся: если бот не появился в сети, смотрите журнал — код
закрытия 4004 означает неверный токен, 4014 — запрошено запрещённое
намерение.

## Что делать при утечке ключа

1. **Токен бота** — `/revoke` у @BotFather, затем новый в `.env`.
2. **Gemini** — удалить ключ в AI Studio, создать новый.
3. **api_id / api_hash** — сменить нельзя, они привязаны к аккаунту;
   при подозрении обращайтесь в поддержку Telegram.
4. **Пароль базы** — сменить в `.env`; при PostgreSQL придётся пересоздать
   том, пароль задаётся только при инициализации.

Файл `.env` хранится с правами 600 и не попадает в git — это прописано
в `.gitignore`. В журналы установки секреты не пишутся, в архиве
`collect-logs.sh` они вырезаются.
